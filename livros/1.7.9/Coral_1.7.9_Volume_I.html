1. O que é Coral

Objetivo de leitura

Entender o que é um programa e reconhecer uma instrução Coral.

Antes de começar

Nenhum conhecimento de programação é necessário.

Coral é uma linguagem de programação em português corrente controlado. Um programa é uma sequência de instruções que o computador executa. Antes de estudar instalação e ferramentas, veja um programa inteiro:

Código Coral
mostre "Olá, Coral"
Saída esperada
Olá, Coral

O comando mostra Olá, Coral e termina a linha. O texto entre aspas é um valor; mostre é a instrução que o exibe. No Cap. 7 você executa e modifica esse programa passo a passo.

A Coral é usada em scripts, projetos com vários arquivos, simulações, dados e aplicações. A escrita natural tem formas definidas: você aprende essas formas em exemplos e consulta seus contratos nas fichas. Não é preciso saber Python para iniciar; a integração com Python é apresentada no Volume II, Parte V.

Este volume foi organizado para estudantes, professores e pessoas que desejam construir programas reais. Siga os capítulos na ordem ou use o índice remissivo para consultar um recurso. As seções Para ir além aprofundam o tema sem interromper a primeira leitura.

O que você aprendeu

Um programa reúne instruções. Em mostre "Olá, Coral", a instrução é mostre e o valor é o texto entre aspas.

Prática

Escreva um programa que mostre seu nome e o nome Coral em duas linhas.

Conferir a resposta comentada

Use duas instruções mostre, uma com o seu nome entre aspas e outra com "Coral". Cada instrução termina sua saída com uma quebra de linha.

2. Instalando Coral

Objetivo de leitura

Escolher um modo de instalação e preparar os arquivos necessários.

Antes de começar

Leia o capítulo 1; tenha acesso ao pacote de distribuição.

Há quatro caminhos oficiais, todos apoiados pela mesma base de runtime.

Coral Setup, recomendado para uso comum

Abra Instalacao/Coral_Setup.cmd no Windows ou Instalacao/Coral_Setup.sh em sistemas POSIX. A interface usa o contrato coral.manager/1: não existe um segundo instalador escondido na GUI.

Coral Manager, recomendado para automação e diagnóstico

Terminal
python Instalacao/Runtime/coral-1.7.6.pyz manager diagnosticar --json
python Instalacao/Runtime/coral-1.7.6.pyz manager instalar --runtime coral-1.7.6.pyz --perfil estudante --json
python Instalacao/Runtime/coral-1.7.6.pyz manager instalar --runtime coral-1.7.6.pyz --perfil estudante --aplicar --json

Operações mutáveis produzem primeiro um plano. A alteração é aplicada apenas quando o usuário pede explicitamente.

Runtime portátil

Terminal
python3 Instalacao/Runtime/coral-1.7.6.pyz --versao
python3 Instalacao/Runtime/coral-1.7.6.pyz meu_programa.coral

Desenvolvimento do compilador

Terminal
python -m venv .venv
# Linux/macOS
source .venv/bin/activate
# Windows PowerShell
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
python -m coral --self-check

A instalação persistente continua disponível pelos assistentes em Instalacao/Assistentes.

Uso sem internet

O pacote completo pode ser transferido por outro computador, dispositivo de armazenamento ou rede local. O runtime portátil Instalacao/Runtime/coral-1.7.6.pyz usa o Python disponível e inclui o núcleo Coral. Na máquina alvo, execute python3 Instalacao/Runtime/coral-1.7.6.pyz --versao e depois um arquivo Coral.

Isso não significa que toda opção do Setup seja offline. Perfis com dependências opcionais exigem que os pacotes estejam previamente disponíveis; a instalação por pip com downloads não funciona desconectada. Para o editor, transfira também o VSIX da distribuição e instale o arquivo localmente. Consulte o Cap. 5.

A instalação nativa e os pacotes de sistema possuem requisitos próprios. Consulte o Volume II, Parte III, seção Instalação, antes de escolher um fluxo para máquinas sem conexão.

O que você aprendeu

Setup orienta a instalação comum; Manager permite automação; o runtime portátil executa arquivos. Dependências opcionais precisam ser obtidas separadamente quando usadas.

Prática

Escolha a instalação para uma máquina sem internet e identifique o que precisa transferir antes.

Conferir a resposta comentada

Transfira o pacote completo da release e, quando houver dependências opcionais, os pacotes dessas dependências para a plataforma alvo. O runtime portátil do pacote não precisa baixar dependências do núcleo. A instalação com pip só é offline quando todos os wheels necessários estão disponíveis.

4. Outras plataformas suportadas

Objetivo de leitura

Distinguir portabilidade do núcleo e validação de uma plataforma.

Antes de começar

Conheça os caminhos de instalação do capítulo 2.

Linux é a plataforma autoritativa da Coral 1.7.6. Os fluxos e scripts preservados para Windows não representam uma qualificação nativa dessa plataforma nesta release. macOS também não recebe, nesta edição, a mesma declaração de evidência Linux.

O que você aprendeu

Linux é a plataforma autoritativa desta edição. Um script disponível em outro sistema não comprova sua execução nem o funcionamento de drivers e janelas.

Prática

Explique por que possuir um script Windows não comprova a qualificação daquela plataforma.

Conferir a resposta comentada

O script registra um fluxo de instalação, mas a qualificação exige sua execução na plataforma. A 1.7.5 considera Linux autoritativo e não promete evidência nativa Windows.

5. VS Code

Objetivo de leitura

Selecionar o runtime no VS Code e usar execução, depuração e auxílio à escrita.

Antes de começar

Instale Coral e VS Code; consulte os capítulos 2 e 3.

A extensão oficial é Coral Language 0.77.0.

Instalar

Use coral-language-0.77.0.vsix da pasta Instalacao/Extensao_VSCode. Depois execute Developer: Reload Window.

Confirmar o runtime

Use Coral: Mostrar runtime selecionado. A extensão respeita configuração explícita e, na ausência dela, consulta a instalação persistente.

Executar

Coral: Executar arquivo no terminal usa o runtime selecionado e mantém entrada e saída no terminal.

Depurar com F5

Abra um arquivo .coral, coloque um breakpoint e pressione F5. O DAP suporta breakpoints no arquivo principal e em módulos .coral locais importados, pilha, variáveis, evaluate e step in/over/out.

Estudar o código

O Modo Aprender e o Coral Ensinar explicam o programa sem exigir alteração do código fonte. O estudo automático no editor é opcional e pode ser ligado ou desligado pelo usuário.

Componentes e diagnóstico

A extensão também oferece comandos para verificar suporte opcional, instalar componentes pelo gerenciador oficial, abrir o Coral Manager e diagnosticar a integração VS Code.

Reconhecer símbolos pelas cores

A Coral 1.7.4 informa ao editor o papel dos símbolos que consegue resolver: classes, tipos, parâmetros, propriedades, variáveis, funções, métodos e módulos. A aparência depende do tema do VS Code. Para ligar ou desligar esse recurso, use coral.semanticColoring.enable.

Em dieta do tipo Dieta, o primeiro nome é um parâmetro e o segundo é uma classe. Em defina seu dieta como dieta, seu dieta é uma propriedade e a última ocorrência é o parâmetro. A diferença ajuda a ler o código sem mudar sua execução.

Se o código estiver incompleto ou a análise não puder comprovar um vínculo, o realce básico continua disponível. Uma cor não comprova que o programa está correto.

Escrever blocos e completar nomes

A opção coral.editor.autoCloseBlocks insere um corpo indentado e fim alinhado ao pressionar Enter após uma abertura completa. O completamento usa o contexto para sugerir nomes. Confira a sugestão selecionada antes de aceitar com Tab.

Em um coral.toml vazio, o comando Coral: Inserir estrutura básica do coral.toml cria o manifesto inicial. O arquivo possui um ícone próprio que acompanha temas claros e escuros.

Exemplo: parâmetro, propriedade e classe

Código Coral
crie a classe Dieta
fim
crie a classe Pessoa
    ao criar uma Pessoa com dieta do tipo Dieta
        defina seu dieta como dieta
    fim
fim
defina plano como Dieta()
defina pessoa como Pessoa(plano)
mostre "Pessoa criada"
Saída esperada
Pessoa criada

No construtor, Dieta designa a classe do parâmetro dieta. A atribuição guarda esse argumento na propriedade do objeto. O editor diferencia esses papéis quando consegue resolver os símbolos.

Consultas de tipo e chamadas em bloco na 1.7.5

Depois de animal for do tipo, o autocomplete oferece tipos nativos e classes válidas disponíveis no escopo. O nome da classe recebe realce de tipo; quando seu vínculo é comprovado, hover apresenta a declaração e a hierarquia, e ir para definição abre a declaração.

Ao pressionar Enter depois de chame alvo com, o editor acompanha a indentação e o argumento corrente. O fechamento automático respeita coral.editor.autoCloseBlocks. A ajuda de assinatura também atende construtores e métodos. A tolerância do editor a uma chamada incompleta serve para continuar digitando; o compilador ainda exige o fechamento correto.

Documentos abertos prevalecem sobre as cópias no disco. Ao fechar o arquivo, o editor volta a considerar a versão salva. Alterações de interface revalidam os consumidores afetados; não é preciso renomear arquivos ou reiniciar o editor para obter a atualização normal do índice.

O que você aprendeu

Executar mostra o comportamento do programa; depurar permite acompanhar seu estado. Completamento e cores auxiliam a escrita, mas não comprovam correção.

Prática

Localize a configuração de runtime da extensão e compare executar com depurar.

Conferir a resposta comentada

Executar inicia o programa no terminal. Depurar por F5 também conecta o adaptador e permite observar pontos de parada, pilha e variáveis. O runtime escolhido precisa corresponder à versão da aplicação.

8. Como ler exemplos e fichas de API

Objetivo de leitura

Distinguir explicação, código, terminal, saída e contrato de uma função.

Antes de começar

Reconheça um exemplo simples do capítulo 7.

O que escrever e o que observar

A Coral usa palavras em português, mas segue formas definidas. A frase de uma explicação e a instrução de um programa têm papéis diferentes. Neste livro, trechos como defina pontos como 10 recebem fonte própria e fundo discreto, mesmo dentro de um parágrafo.

Os exemplos em bloco possuem rótulos:

Rótulo Como usar
Código Coral Escreva ou copie em um arquivo .coral
Terminal Execute no terminal, na pasta indicada
Saída esperada Compare com o resultado; não copie para o programa
Configuração Salve no arquivo de configuração indicado
Assinatura para consulta Consulte os argumentos; não execute a assinatura como programa

Quando um exemplo não imprime texto, o livro informa isso em uma nota. O programa ainda pode criar valores, salvar arquivos ou alterar estado.

Ler o realce do código

Nos blocos Coral, palavras da linguagem, tipos e valores especiais recebem negrito. Instruções como defina se distinguem de nomes como pontos, escolhidos pelo programador. Aspas identificam textos; números mantêm sua escrita literal; comentários aparecem em tom discreto. A fonte monoespaçada, o fundo creme e o rótulo Código Coral distinguem o programa da explicação. O vermelho da marca aparece na faixa de anéis, sem reduzir o contraste do texto.

O realce do livro reconhece a escrita dos tokens. Ele não descobre o tipo de todo objeto nem valida o programa. A extensão do editor pode acrescentar informação semântica quando consegue resolver os símbolos.

Ler uma assinatura

Uma assinatura mostra como chamar uma função. Em inteiro(valor, padrao=<ausente>), valor é obrigatório e padrao é opcional. Na chamada inteiro("12"), o texto "12" é o argumento. O retorno é o valor devolvido, neste caso 12.

Termo Significado
Parâmetro Nome previsto na declaração da função
Argumento Valor fornecido em uma chamada
Valor padrão Alternativa usada quando o argumento opcional é omitido
Retorno Valor que a operação devolve ao programa

As assinaturas extraídas do runtime usam notação Python para mostrar o contrato completo. None corresponde ao valor nulo da escrita Coral. <ausente> significa que o argumento não foi fornecido, o que é diferente de fornecer nulo. * separa parâmetros que precisam de nome; / identifica os apenas posicionais; *partes aceita vários argumentos posicionais.

Consultar uma ficha sem interromper o estudo

Primeiro entenda a intenção e o exemplo do capítulo. Depois consulte a ficha para conferir assinatura, tipos, obrigatoriedade, valores padrão, retorno, erros e observações. As fichas permanecem completas; no HTML, você pode abrir a seção de consulta quando precisar.

Uma forma natural é uma expressão oficial que corresponde a uma operação. converta "12" para inteiro, por exemplo, corresponde a inteiro("12"). A Coral não tenta adivinhar qualquer frase em português.

No HTML, ajuste fonte, largura e tema na barra de leitura. O botão Copiar copia apenas o conteúdo do bloco. As respostas ficam recolhidas para você tentar a atividade antes de conferir. No PDF, respostas e aprofundamentos aparecem por inteiro.

O Apêndice A reúne termos; o Apêndice C ajuda a localizar recursos. O Volume II contém a referência normativa e a arquitetura.

O que você aprendeu

Código é o que você escreve; saída é o que observa. Parâmetro é o nome declarado; argumento é o valor fornecido; retorno é o valor devolvido pela operação.

Prática

Diferencie parâmetro, argumento, padrão e retorno em uma ficha.

Conferir a resposta comentada

Parâmetro é o nome previsto pela função; argumento é o valor fornecido numa chamada; padrão é o valor usado quando um argumento opcional é omitido; retorno é o valor devolvido ao chamador.

9. Valores e variáveis

Objetivo de leitura

Criar uma variável, alterar seu valor e mostrar o resultado.

Antes de começar

Conheça mostre, apresentado no capítulo 7.

Guardar um valor

Uma variável associa um nome a um valor. Podemos usar o nome pontos para guardar a pontuação de um jogador. Para começar com dez pontos, escrevemos:

Código Coral
defina pontos como 10

Este exemplo não imprime texto no terminal.

Leia a instrução por partes:

Trecho O que significa
defina Inicia a instrução de atribuição
pontos É o nome que receberá o valor
como Separa o nome do valor
10 É o valor inicial

O nome pontos foi escolhido por nós. Você pode usar outro nome, desde que o escreva da mesma maneira nas instruções seguintes. Guardar um valor não significa mostrá lo no terminal.

Alterar e mostrar

Agora vamos acrescentar cinco pontos e retirar dois. A instrução mostre pontos exibe o valor que ficou guardado.

Arquivo completo de apoio: Exemplos/Citados/Fundamentos/01_fluxo_e_colecoes.coral.

Código Coral
defina pontos como 10
adicione 5 a pontos
subtraia 2 de pontos
mostre pontos
Saída esperada
13

O programa executa as instruções em ordem:

Depois da instrução Valor de pontos
defina pontos como 10 10
adicione 5 a pontos 15
subtraia 2 de pontos 13

Atenção ao nome e ao texto

Funções como valores

Uma função pode ser atribuída a uma variável, recebida como argumento ou retornada. Uma função anônima pode ser escrita como função anônima com x que retorna x vezes 2. Isso é uma expressão; atribua o resultado a um nome antes de usar, quando precisar de uma operação identificável.

Decoradores são declarados com decore com decorador antes da função. Eles exigem um objeto chamável previamente definido e são um recurso avançado de interoperabilidade. Prefira funções comuns até existir uma razão concreta para modificar o comportamento de outras funções.

Não existe uma promessa de cobertura estática equivalente a linguagens com verificação obrigatória de tipos. Testes e validação de entradas continuam necessários.

Chamadas explícitas em várias linhas

Use chame quando a chamada participa da organização natural do programa; execute funcao(...) continua disponível para executar a função por seu efeito. Um padrão é avaliado uma vez na criação da função, conforme o contrato existente; mover sua escrita para outra linha não muda esse momento.

Tipos estruturais e parâmetros variádicos conservam suas regras. Uma chamada multilinha usada como padrão fecha com seu próprio fim, antes do fim com da declaração. Regras de contexto

aguarde, laços assíncronos e contextos assíncronos exigem função ou método assíncrono. Não copie apenas uma linha aguarde para o topo de um arquivo e espere que funcione. O exemplo inclui a estrutura necessária.

Definir a entrada da aplicação

Quando o arquivo é executado diretamente, a Coral inicializa primeiro o módulo inteiro e depois inicia o bloco programa principal uma única vez. Isso permite declarar funções e classes abaixo do bloco e utilizá las dentro dele. Quando o mesmo arquivo é importado como módulo, a entrada não é iniciada.

O bloco não recebe parâmetros, não possui anotação de retorno e não cria uma função pública chamada principal. Uma função comum com esse nome continua válida e precisa ser chamada normalmente. Também não é permitido devolver um valor da entrada. Um retorne vazio pode encerrar o bloco antecipadamente.

Código Coral
mostre "Olá"
Saída esperada
Olá

chame e execute

chame nome com argumentos é a forma corrente da Coral para invocar uma função pelo nome e por seus argumentos, especialmente quando a intenção é realizar uma ação e ignorar o valor devolvido.

execute EXPRESSAO executa uma expressão de chamada por efeito. É útil para chamadas explícitas como execute objeto.metodo(1) ou quando a forma de expressão é mais adequada. Para consumir um retorno, use a chamada dentro de uma expressão, por exemplo em defina ou mostre.

Nenhuma dessas formas é usada para iniciar programa principal. A própria execução direta do arquivo inicia o bloco automaticamente.

Importação

Um arquivo que contém programa principal ainda pode ser usado como módulo. A importação disponibiliza seus símbolos públicos, mas não inicia a aplicação. Isso evita efeitos inesperados em testes, bibliotecas e projetos com vários módulos.

Editor

A extensão Coral reconhece a entrada no outline, hover, dobramento, indentação e realce. Ao pressionar Enter no cabeçalho, o fechamento com fim segue a configuração de fechamento automático de blocos. O snippet de entrada principal permanece uma escolha contextual e não substitui automaticamente identificadores digitados pelo usuário.

Onde a entrada pode aparecer

A entrada não pode ficar dentro de condição, repetição, função, classe, tente ou combinar. Só pode existir uma entrada principal válida por módulo. REPL e execução interativa de trechos rejeitam esse bloco porque não representam a execução completa do módulo.

O que você aprendeu

O bloco programa principal é opcional. A execução direta o inicia após inicializar o módulo; uma importação não inicia esse bloco.

Prática

Conferir a resposta comentada

A execução direta inicializa o módulo inteiro e só depois inicia a entrada, portanto a função já está disponível. A importação disponibiliza os símbolos, mas não inicia o bloco principal.

23. Conversões

Objetivo de leitura

Converter valores e escolher como tratar uma entrada inválida.

Antes de começar

Conheça tipos e entrada de teclado, dos capítulos 10 e 22.

Uma entrada de teclado é texto. Converter significa produzir um valor com outro tipo antes de usá lo no cálculo. Coral oferece inteiro, decimal, texto e booleano.

Código Coral
de coral.conversoes importe inteiro, decimal
mostre inteiro("12")
mostre decimal("2,5")
mostre tente converter "inválido" para inteiro, senão nulo
Saída esperada
12
2.5
None

A saída é 12, 2.5 e None, em linhas separadas. A conversão estrita não transforma um número fracionário em inteiro por truncamento e não aceita booleano como inteiro implícito. Em texto decimal, ponto ou vírgula são aceitos, mas sua mistura é ambígua.

Um valor padrão é devolvido quando a conversão falha. Sem padrão, o erro público é ErroConversao. A forma natural e a API explícita têm o mesmo contrato. Argumentos são avaliados uma vez; o padrão também é avaliado numa conversão bem sucedida. Consulte o Cap. 18 para tratamento de erros.

24. Texto

Objetivo de leitura

Limpar espaços e transformar textos sem alterar o valor original.

Antes de começar

Conheça textos e chamadas de função.

Texto guarda caracteres e preserva espaços dentro de aspas. Para limpar uma entrada, use aparar; para comparações com uma regra de caixa explícita, use maiusculas ou minusculas.

Código Coral
de coral.texto importe aparar, maiusculas
mostre maiusculas(aparar("  Coral  "))
mostre "coral" começa com "co"
Saída esperada
CORAL
True

A saída é CORAL e True, em linhas separadas. Essas operações produzem texto ou respostas novas; não alteram a string original. Prefixos e sufixos são comparados exatamente como fornecidos. Normalização Unicode, caixa e equivalência cultural são decisões distintas; não remova acentos ou normalize nomes automaticamente sem um motivo.

Índices e fatias são ensinados no Cap. 14. Para a família completa, consulte o Volume II, Parte II, seção Biblioteca coral.texto.

Textos com várias linhas

Na Coral 1.7.9, três aspas duplas ou três aspas simples delimitam um texto multilinha. O recurso é geral: serve para SQL, HTML, Markdown, mensagens extensas e outros conteúdos textuais. Ele não executa nem interpreta o conteúdo.

Quando a abertura termina a linha e o conteúdo começa na linha seguinte, essa primeira quebra é estrutural. Se o fechamento também fica sozinho em sua linha, a última quebra estrutural é removida. O recuo comum é retirado e o recuo relativo interno é preservado.

Código Coral
defina mensagem como """
    primeira linha
      segunda linha
    terceira linha
"""
mostre mensagem
Saída esperada
primeira linha
  segunda linha
terceira linha

O corpo é opaco para a estrutura do programa. Palavras como fim, parênteses, comentários aparentes e nomes que parecem imports continuam sendo caracteres do texto. Strings de uma linha continuam com o mesmo comportamento das versões anteriores. Se o fechamento faltar, o editor aponta o início do literal com o diagnóstico P180.

Processar arquivos e CSV aos poucos

Quando os dados crescem, um iterador permite processar um registro de cada vez. Um lote reúne uma quantidade limitada de registros para uma etapa de trabalho. Isso reduz a necessidade de guardar todos os dados na memória, embora o tamanho de cada registro ainda importe.

    para cada lote em lotes faça
        mostre tamanho de lote
    fim
fim
Saída esperada

A abertura acontece no primeiro avanço, não na construção do leitor. O leitor é de passagem única e fecha no fim ou em erro. Para parar antes, use com ou fechar(); não dependa da coleta de lixo. Linhas de texto conservam suas quebras; registros CSV podem conter vírgulas e quebras dentro de aspas. Cabeçalhos devem ser únicos, não vazios, e as linhas precisam manter a largura.

Os escritores exigem textos, consomem gradualmente e substituem o destino. Não inserem quebras em escrever_linhas nem convertem valores implicitamente em escrever_csv; um erro pode deixar destino parcial. Um leitor usado como entrada de um escritor deve continuar sob o com externo do chamador. coral.formatos.de_csv continua materializando dados, conforme seu contrato anterior.

Veja o projeto executável Exemplos/Projetos/Importador_Gradual: lotes de dois registros, filtro ativo igual a sim, nomes aparados e saída nome,valor. As fichas deste capítulo detalham cada contrato. A referência completa está no Volume II e em Documentacao/Usuario/Coral_Arquivos_CSV_1_7_7.md.

Para sequências de campos, nomes não são inferíveis: sem colunas explícitas, não é emitido cabeçalho mesmo com cabecalho=True. Objetos permitem inferir nomes na ordem do primeiro registro; colunas explícitas definem nomes e ordem.

Validar registros externos com esquemas

Na Coral 1.7.8, coral.esquemas descreve contratos de cadastro, pesquisa e inventário com quatro chamadas explícitas: campo, esquema, validar_registro e validar_registros. Nenhuma forma natural nova foi criada. A validação aceita ou relata dados; não converte textos, não preenche valores padrão e não altera a entrada.

Ausência significa que a chave não existe. Nulo significa que a chave existe com nulo. Um campo opcional pode estar ausente e ainda recusar nulo; um campo obrigatório e anulável exige a chave, mas aceita nulo. Inteiro rejeita booleanos; decimal aceita números finitos e rejeita booleanos. Limites são inclusivos.

Erros contêm campo, regra, mensagem, registro, linha e origem, sem copiar valores sensíveis. A ordem declarada dos campos determina a ordem do diagnóstico; extras recusados vêm depois, na ordem do registro. Tipo incompatível não avalia limites desse campo. modo="primeiro" para no primeiro erro; modo="coletar" para ao atingir limite_erros, inteiro positivo que não aceita booleano. interrompido sinaliza a política, sem alegar que o restante foi examinado. verificados conta somente registros consumidos.

Um jogo reaberto usa BackendNulo, começa parado e restaura somente estado persistente. Combates contextuais preservam participantes, ordem, índice e rodada utilizando as entidades reconstruídas do Mundo.

SQLite local na Coral 1.7.9

Para aplicações que precisam consultar dados depois de encerrar o programa, coral.sqlite oferece uma camada pequena sobre SQLite. SQL permanece explícito. Valores entram por parâmetros separados do texto SQL; parâmetros não substituem nomes de tabela, coluna ou fragmentos de consulta.

Código Coral
de coral.sqlite importe abrir

defina banco como abrir(":memoria:")
defina criar_tabela como """
    CREATE TABLE itens (
        id INTEGER PRIMARY KEY,
        nome TEXT NOT NULL,
        quantidade INTEGER NOT NULL
    )
"""
execute banco.executar(criar_tabela)
execute banco.executar("INSERT INTO itens(nome, quantidade) VALUES (?, ?)", ["Ana", 3])
execute banco.confirmar()
defina item como banco.consultar_um("SELECT nome, quantidade FROM itens WHERE nome = ?", ["Ana"])
mostre item["nome"]
mostre item["quantidade"]
execute banco.fechar()
Saída esperada
Ana
3

abrir(caminho, timeout=5.0) devolve uma Conexao. O caminho especial :memoria: cria um banco temporário em memória. timeout deve ser numérico, não negativo, e booleanos não são aceitos como números nesse contrato.

Operação da conexão Contrato de uso
executar(sql, parametros=()) Executa um comando e retorna linhas_afetadas e ultimo_id.
executar_muitos(sql, parametros) Executa o mesmo comando para um iterável de sequências ou mapeamentos.
consultar(sql, parametros=()) Materializa todas as linhas como lista de dicionários.
consultar_um(sql, parametros=()) Retorna um dicionário ou nulo quando não há linha.
confirmar() Confirma alterações pendentes.
reverter() Desfaz alterações pendentes desde a última confirmação.
transacao() Contexto explícito: confirma na saída normal e reverte se o bloco falhar.
fechar() Encerra a conexão; é idempotente. Uso posterior da conexão falha.

Parâmetros aceitam sequência ou mapeamento. Texto e bytes isolados são recusados para evitar vinculação acidental caractere a caractere. executar_muitos exige um iterável de conjuntos de parâmetros. Erros operacionais do SQLite são expostos como ErroOperacionalSQLite; demais falhas da camada usam ErroSQLite, preservando a causa original.

Uma transação contextual não pode ser aninhada e não começa se já houver alteração pendente. A API não cria savepoints implícitos. Para um banco em arquivo, confirme antes de fechar quando quiser conservar as alterações. 30. Projetos, módulos e coral.toml

Objetivo de leitura

Separar módulos, configurar a entrada e executar um projeto completo.

Antes de começar

Conheça funções, classes e o projeto básico do capítulo 6.

Criar a estrutura

Terminal
coral novo MinhaFerramenta --template basico
cd MinhaFerramenta
coral executar
coral testar

coral.toml identifica a raiz do projeto. Ele pode definir nome, versão, arquivo de entrada, requisito de versão Coral, caminhos de módulos e caminhos de testes.

Configuração TOML
[projeto]
nome = "minha-ferramenta"
versao = "0.1.0"
[coral]
versao = ">=1.7.4"
[entrada]
arquivo = "principal.coral"
[modulos]
caminhos = ["."]
[testes]
caminhos = ["testes"]

Caminhos são relativos à raiz configurada. coral executar compila os módulos para .coral_build e executa a entrada. Essa pasta contém saída regenerável. Não a use como local dos seus arquivos fonte.

Importar funções locais

Um arquivo calculos.coral pode declarar uma função media. Em principal.coral, use de calculos importe media e depois media(notas). Nomeie seus módulos de forma clara e evite colidir com coral, json, sys e outros módulos do ambiente.

Na 1.5.8, a interface pública do módulo também carrega formas naturais exportadas. Uma função declarada com uma forma como "dobre {numero}" pode ser usada pelo consumidor após uma importação seletiva. Alias de importação preserva a forma adaptada, enquanto duas formas externas ambíguas produzem diagnóstico em vez de uma escolha silenciosa.

O build guarda hashes de fonte e de interface. Sem mudança, módulos já válidos são reutilizados. Uma mudança apenas de implementação recompila o módulo afetado; uma mudança de interface também invalida os consumidores. O resultado de um build incremental deve ser equivalente ao de um build limpo.

Recursos de projeto precisam ser declarados no coral.toml. O build copia somente os recursos declarados e o runtime resolve seus caminhos a partir do pacote construído, de modo que a pasta de build possa ser movida sem perder o vínculo com esses arquivos.

A execução de um arquivo isolado não equivale à construção de um projeto: para módulos locais Coral, prefira coral executar na raiz do projeto. O comando coral arquivo.coral é apropriado a programas independentes.

Projeto curto: Cadastro em três arquivos

Separe as classes, a aplicação e os testes de um cadastro. Declare o arquivo de entrada no coral.toml.

A orientação de solução está no Apêndice B, seção Projeto 30.

Contratos entre módulos na 1.7.4

Quando uma classe ou função possui tipos declarados, a análise do consumidor aproveita essa informação. Imports seletivos, aliases e reexportações preservam a origem do símbolo quando ela pode ser resolvida. Métodos herdados e o construtor herdado também podem fornecer contratos.

O editor usa os arquivos abertos para analisar alterações ainda não salvas. Ao mudar o contrato de um módulo, os consumidores abertos recebem diagnósticos atualizados. A análise não executa os módulos importados para descobrir seus tipos.

O build incremental considera o contrato público das dependências transitivas. Por isso, mudar uma assinatura atrás de um módulo que a reexporta também invalida o consumidor. Alterações somente no corpo preservam o contrato público.

O projeto completo de demonstração está em Exemplos/Citados/Analise_1_7_4/Cadastro: leia modelos.coral, fachada.coral e principal.coral e execute seus testes na raiz do projeto.

Imports seletivos em linhas separadas

Uma linha que termina em de modulo importe abre uma lista de nomes exportados. Cada linha recebe um nome, com alias opcional; fim fecha a importação. Esse bloco não possui corpo de execução.

Código Coral
de math importe
    sqrt como raiz
    floor
fim
mostre raiz(9)
mostre floor(2.8)
Saída esperada
3.0
2

Isso equivale a de math importe sqrt como raiz, floor. A resolução do módulo, os aliases e a ordem de importação permanecem os mesmos. A lista explícita não aceita curingas nem itens vazios. O editor mantém a navegação entre cada item e sua declaração de origem.

Um ambiente próprio para o projeto

Na Coral 1.7.6, [dependencias].python declara requisitos Python e [ambiente].python limita o interpretador. O fluxo resolve wheels para um alvo específico, registra versões e hashes em coral.lock, prepara uma geração isolada e verifica essa geração antes de executar. A execução de arquivo, projeto, build e testes pela CLI usa o mesmo executor quando o projeto adota esse lock.

Configuração TOML
[projeto]
nome = "meu-projeto"

[coral]
versao = ">=1.7.6"

[dependencias]
python = ["biblioteca-didatica==1.0"]

[ambiente]
python = ">=3.10,<3.15"

O nome acima é ilustrativo. Para um fluxo executável sem registro remoto, use Exemplos/Projetos/Ambiente_Reproduzivel, que gera suas próprias wheels didáticas. Com uma pasta de wheels compatíveis, o fluxo é:

Terminal
coral manager ambiente resolver --projeto . --cache wheels --offline --json
coral manager ambiente preparar --projeto . --offline --aplicar --json
coral manager ambiente verificar --projeto . --json
coral executar

Sem --permitir-rede, a resolução não consulta um registro remoto. Preparar sem --aplicar apenas apresenta o plano. Uma falha na instalação conserva a geração ativa anterior; repetir a preparação reutiliza uma geração válida. Um ambiente ausente, alterado ou incompatível impede a execução de um projeto que adotou lock. Projetos antigos sem lock conservam seu fluxo anterior.

Esta edição aceita wheels e requisitos de nome e versão. URLs, caminhos, VCS, extras e marcadores escritos no manifesto ficam fora desse contrato inicial. O lock pertence ao alvo registrado: não copie uma venv pronta para outra máquina ou caminho. Veja Documentacao/Usuario/Coral_Ambientes_Reproduziveis_1_7_6.md para restrições, cancelamento e os limites de qualificação.

O que você aprendeu

O manifesto organiza o projeto. Imports disponibilizam símbolos; alterações de contrato podem exigir reconstruir consumidores.

Prática

Diferencie arquivo de entrada, importação e bloco programa principal.

Conferir a resposta comentada

O projeto escolhe qual arquivo executar; a importação carrega um módulo; o bloco principal organiza a ação da execução direta. Bibliotecas reutilizáveis não devem iniciar a aplicação durante a importação.

Testes nativos

32. Regras, eventos e tempo

Objetivo de leitura

Reagir a eventos e mudanças e controlar o tempo lógico.

Antes de começar

Conheça condições e estado, dos capítulos 9 e 12.

A ideia principal da programação reativa em Coral é simples: algo acontece e uma regra reage. O programa não precisa transformar cada comportamento em um loop manual nem em callbacks de baixo nível. A superfície natural descreve o acontecimento, a condição opcional e a reação; o runtime mantém ordem determinística, tempo lógico e rastreamento.

O exemplo canônico mais curto está em Exemplos/Regras/01_eventos_observacao_e_tempo.coral:

Código Coral
defina ultimo_dano como 0
quando ocorrer "dano" como evento se evento.quantidade for maior que 3
    defina ultimo_dano como evento.quantidade
    mostre evento.origem
fim

emita o evento "dano" com quantidade 5 e origem "espada"
Saída esperada
espada

O objeto evento expõe os dados nomeados do acontecimento. Nesse exemplo, quantidade é carga útil e origem identifica quem publicou o evento. A emissão é local e determinística: ela não cria uma thread, não inicia uma tarefa em segundo plano e não transforma o programa em um sistema distribuído.

Observar mudanças sem inventar eventos manuais

Quando a intenção é reagir a um valor que mudou, diga isso diretamente:

Código Coral
defina vida como 10
quando vida mudar
    mostre vida
fim

avalie as regras
defina vida como 9
avalie as regras
Saída esperada
9

Também existem cruzamentos de limite:

Código Coral
quando temperatura passar de 40
    mostre "Temperatura alta."
fim

quando temperatura cair abaixo de 30
    mostre "Temperatura baixa."
fim

Este exemplo não imprime texto no terminal.

O exemplo executável é Exemplos/Regras/01_eventos_observacao_e_tempo.coral. Uma atribuição que mantém o mesmo valor não conta como mudança. passar de e cair abaixo de reagem ao cruzamento da fronteira, não a toda avaliação posterior que permaneça do mesmo lado.

Prioridade, cancelamento e consumo

Prioridades nomeadas evitam números mágicos: baixa, normal, alta e crítica. Reações de maior prioridade são consideradas primeiro; empates preservam a ordem de registro.

Código Coral
quando ocorrer "rpg.dano.antes" como evento com prioridade crítica
    cancele evento
fim

Este exemplo não imprime texto no terminal.

Cancelar só tem efeito sobre acontecimentos declarados como canceláveis e deve ocorrer antes do efeito. A Coral não tenta desfazer uma alteração já aplicada. O RPG usa esse contrato em rpg.dano.antes: se o evento for cancelado, a vida não é modificada. Veja Exemplos/Regras/02_prioridade_e_cancelamento.coral.

consuma evento tem outro significado: impede que o acontecimento continue sua propagação para níveis superiores, mas não representa por si só o cancelamento da operação de domínio.

Limites, cooldown e debounce

Uma reação pode executar somente uma vez ou um número máximo de vezes:

Código Coral
uma vez quando ocorrer "visita"
    mostre "Primeira visita."
fim

Este exemplo não imprime texto no terminal.

Cooldown limita a frequência de um evento:

Código Coral
quando ocorrer "ataque" no máximo uma vez a cada 2 segundos
    mostre "Ataque aceito."
fim

Este exemplo não imprime texto no terminal.

Debounce é adequado quando a ação deve ocorrer somente depois de um período sem novas mudanças:

Código Coral
quando texto mudar espere 300 milissegundos sem novas mudanças faça
    mostre texto
fim

Este exemplo não imprime texto no terminal.

Essas formas usam o tempo lógico do motor. Não usam sleep escondido.

Tempo determinístico e relógio de teste

Temporizadores continuam disponíveis com depois de e a cada. Em testes, o relógio pode ser avançado instantaneamente:

Código Coral
defina pulsos como 0
a cada 2 segundos faça
    adicione 1 a pulsos
fim

avance o relógio de teste em 5 segundos
mostre pulsos
Saída esperada
2

O exemplo Exemplos/Regras/01_eventos_observacao_e_tempo.coral valida tempo sem esperar cinco segundos reais. Isso mantém testes rápidos e reproduzíveis.

Grupos e regras temporárias

Regras nomeadas podem ser reunidas em grupos:

Código Coral
regra "chuva_venenosa"
    quando falso
    então
        passe
fim
regra "raios"
    quando falso
    então
        passe
fim
grupo tempestade faça
    use chuva_venenosa
    use raios
fim

desative grupo tempestade
ative grupo tempestade

Este exemplo não imprime texto no terminal.

Uma regra desativada também pode ser ligada por duração ou até uma condição:

Código Coral
defina temperatura como 35
regra "alerta"
    quando temperatura for maior que 30
    então
        passe
fim
ative alerta durante 30 segundos
ative alerta até temperatura for menor que 30

Este exemplo não imprime texto no terminal.

A duração é cooperativa: o motor aplica a expiração quando seu tempo lógico avança.

Sequências de dois acontecimentos

A 1.5.6 reconhece sequências deliberadamente simples A → B:

Código Coral
quando ocorrer "botao_a" e depois ocorrer "botao_b" dentro de 2 segundos
    mostre "Combinação reconhecida."
fim

Este exemplo não imprime texto no terminal.

A janela temporal é opcional. Esta edição não transforma a linguagem em um processador geral de eventos complexos; sequências arbitrariamente longas permanecem fora do escopo.

Eventos espaciais em 2D e 3D

Os observadores espaciais reutilizam a baseline geral da linguagem:

Código Coral
defina jogador como posição(-1, 5)
defina floresta como região(retângulo(0, 0, 10, 10))

quando jogador entrar em floresta
    mostre "Entrou na floresta."
fim

Também há sair de, proximidade, toque e interseção. As mesmas ideias funcionam em 3D; misturar 2D e 3D continua exigindo conversão explícita. O exemplo canônico é Exemplos/Regras/03_eventos_espaciais.coral.

Estados observáveis

Para uma pequena máquina de estados, declare a intenção sem construir uma classe auxiliar:

Código Coral
estado porta começa como fechada

quando ocorrer "abrir_porta"
    mude porta para aberta
fim

Este exemplo não imprime texto no terminal.

Esse recurso é um estado observável leve. Ele não é um statechart hierárquico e não cria estados paralelos implicitamente.

Histórico e explicação

O comando:

Código Coral
mostre histórico de eventos
Saída esperada
Nenhum evento ou regra foi registrado no histórico reativo.

ativa rastreamento detalhado desde o início do programa e apresenta a cadeia de decisões reativas. O runtime registra o resultado de uma condição quando ela é avaliada; o modo Ensinar usa esse registro para explicar por que uma regra executou ou foi suprimida sem reavaliar a condição e sem repetir efeitos colaterais.

Motores e avaliação

avalie as regras processa condições e observadores no motor padrão. atualize as regras por ... segundos também avança tempo lógico, timers, cooldowns, debounce e ativações temporárias. Jogos podem atualizar seu próprio motor durante o ciclo de quadros, enquanto Mundo e RPG publicam acontecimentos de domínio no mesmo modelo de eventos.

Quando nenhum motor específico é informado, a superfície natural usa o motor padrão. Formas históricas como quando ocorrer "moeda" recebendo valor continuam válidas por compatibilidade.

API avançada

A API orientada a objetos permanece em coral.regras, coral.tempo_eventos e módulos auxiliares para ferramentas, integrações e casos que a superfície natural não cobre. Código introdutório deve preferir as frases deste capítulo. regra, eventos, observadores, sequências, grupos e controles reativos são nós do parser e da AST Coral; não dependem de substituição textual frágil nem de interpretação por IA.

33. Mundo

Objetivo de leitura

Organizar valores em células, camadas e regiões de um mapa.

Antes de começar

Conheça coleções e posição como conjunto de coordenadas.

A Coral 1.5.7 introduz uma infraestrutura discreta de mapas em coral.mundo. Ela não é uma engine de jogos: um mapa organiza valores no espaço, permite consultar relações locais e comunica mudanças usando a infraestrutura reativa já existente. O mesmo contrato serve para simulações, ciência, robótica, logística, autômatos celulares e, opcionalmente, jogos.

A ideia central é separar cinco coisas que costumam ser confundidas:

  • uma posição é uma localização contínua no espaço, como (2.4, 7.1);
  • uma célula é uma localização discreta inteira, como (2, 7);
  • uma camada diz que tipo de informação está sendo armazenada;
  • o valor é o dado guardado naquela célula e camada;
  • uma região agrupa células ou associa uma forma espacial a uma parte do mapa.

Célula e posição

Células usam coordenadas inteiras. Uma topologia quadrada usa coluna e linha; uma topologia hexagonal usa q e r; e um mapa voxel usa x, y e z. Posições contínuas continuam pertencendo à baseline espacial apresentada no capítulo anterior.

Código Coral
crie um mapa chamado clima com topologia quadrada
adicione uma camada chamada temperatura ao mapa clima
defina 31.5 na célula (4, 2) da camada temperatura do mapa clima
defina leitura como o valor da célula (4, 2) da camada temperatura do mapa clima
garanta que leitura for igual a 31.5

Este exemplo não imprime texto no terminal.

Ausência não significa nulo, zero, falso ou texto vazio. Uma célula pode simplesmente não possuir conteúdo em determinada camada.

Topologia

A topologia define a dimensionalidade, a forma de vizinhança e a conversão entre célula e coordenada de mundo.

Código Coral
crie um mapa chamado colmeia com topologia hexagonal
defina vizinhas como as células vizinhas de (2, menos 1) no mapa colmeia
garanta que quantidade de vizinhas for igual a 6

Este exemplo não imprime texto no terminal.

Código Coral
crie um mapa chamado volume com topologia voxel
adicione uma camada chamada densidade ao mapa volume
defina 0.82 na célula (3, 4, 5) da camada densidade do mapa volume
defina amostra como o valor da célula (3, 4, 5) da camada densidade do mapa volume
garanta que amostra for igual a 0.82

Este exemplo não imprime texto no terminal.

A topologia quadrada possui quatro vizinhos ortogonais por padrão. A hexagonal possui seis vizinhos axiais. A voxel possui seis vizinhos ortogonais em três dimensões. Mapas podem ser finitos ou não limitados; uma célula ausente em um mapa não limitado continua sendo uma coordenada válida, apenas sem conteúdo.

Camada e valor

Camadas são nomeadas, ordenadas e esparsas. Elas podem armazenar números, textos, booleanos, listas, dicionários e outros valores portáteis reconhecidos pela persistência Coral. BlocoMapa existe como conveniência para terreno ou material, mas não é a unidade obrigatória do sistema.

Código Coral
crie um mapa chamado laboratorio com topologia quadrada
adicione uma camada chamada temperatura ao mapa laboratorio
adicione uma camada chamada umidade ao mapa laboratorio
defina 22.0 na célula (1, 0) da camada temperatura do mapa laboratorio
defina 0.61 na célula (1, 0) da camada umidade do mapa laboratorio
defina t como o valor da célula (1, 0) da camada temperatura do mapa laboratorio
defina u como o valor da célula (1, 0) da camada umidade do mapa laboratorio
garanta que t for igual a 22.0
garanta que u for igual a 0.61

Este exemplo não imprime texto no terminal.

Vizinhança

Vizinhança pertence à topologia, não ao domínio do programa. Isso permite que o mesmo comando seja usado por um autômato celular, um robô ou um jogo.

Código Coral
crie um mapa chamado grade com topologia quadrada
defina proximas como as células vizinhas de (4, 2) no mapa grade
garanta que quantidade de proximas for igual a 4

Este exemplo não imprime texto no terminal.

Consultas de mapa são expressões e podem participar de cálculos e comparações. Por exemplo, soma mais o valor da célula celula da camada temperatura do mapa laboratorio permanece uma única expressão estrutural da linguagem.

Região

Uma região pode ser formada por células explícitas ou, pela API avançada, por uma forma espacial serializável. Regiões discretas servem para setores de armazém, biomas, zonas de segurança, territórios ou qualquer agrupamento irregular.

Código Coral
crie um mapa chamado clima com topologia quadrada
adicione uma camada chamada temperatura ao mapa clima
crie uma região chamada zona_quente no mapa clima com as células [(4, 2), (5, 2), (5, 3)]
defina presentes como as regiões da célula (5, 2) no mapa clima
garanta que quantidade de presentes for igual a 1

Este exemplo não imprime texto no terminal.

Em mapas não limitados, uma região definida por forma não precisa materializar uma quantidade infinita de células. Quando uma enumeração puder ser infinita, a API exige limites explícitos.

Travessia

Travessia é opcional e genérica. Um conteúdo pode permitir ou bloquear passagem, declarar custo não negativo e registrar um motivo. A 1.5.7 fornece adjacência e custos, mas não introduz um algoritmo oficial de caminhos.

Código Coral
crie um mapa chamado deposito com topologia quadrada
adicione uma camada chamada ocupacao ao mapa deposito
coloque o bloco "estante" na célula (8, 3) da camada ocupacao do mapa deposito
bloqueie a travessia pela célula (8, 3) da camada ocupacao do mapa deposito porque "corredor ocupado"

Este exemplo não imprime texto no terminal.

Uma consulta pura de travessia não publica eventos. Uma tentativa explícita pode publicar mapa.travessia_bloqueada no barramento já utilizado pelo mundo.

Eventos de mapa

Mapas associados a Mundo usam o mesmo barramento mundo.regras.eventos; não existe um motor de regras oculto por mapa. Um mapa independente também funciona sem barramento quando o programa não precisa de reatividade.

Código Coral
crie um mapa chamado clima com topologia quadrada
adicione uma camada chamada temperatura ao mapa clima
defina ultima como 0

quando o valor da célula (4, 2) da camada temperatura do mapa clima mudar como evento
    defina ultima como evento.valor_novo
fim

defina 31.5 na célula (4, 2) da camada temperatura do mapa clima
garanta que ultima for igual a 31.5

Este exemplo não imprime texto no terminal.

Também é possível observar entrada e saída de regiões. O resolvedor de localização é relido a cada avaliação, portanto mover o alvo não congela a posição inicial.

Persistência

Mapa participa do envelope coral.persistencia/1 com o identificador coral.mundo/Mapa. O formato recomendado para um mapa isolado é .coralmapa. Topologia, camadas, conteúdos portáteis e regiões são preservados; Pygame, superfícies, callbacks e recursos gráficos abertos não fazem parte do arquivo.

Na API avançada, a persistência genérica já é suficiente:

Código Python
from coral.persistencia import carregar, salvar

salvar(mapa, "clima.coralmapa")
restaurado = carregar("clima.coralmapa")

Mundo também persiste seus mapas nomeados. Documentos de versões anteriores que não possuem o campo mapas continuam sendo carregados com zero mapas.

Visualização opcional com Jogos

coral.jogos não define o significado de um mapa. Ele oferece apenas conversões de tela e um adaptador 2D para mapas quadrados e hexagonais. Mapas voxel continuam válidos no núcleo, mas não recebem uma projeção 3D implícita.

Código Coral
de coral.jogos importe Camera e RenderizadorMapa2D e BackendNulo

crie um mapa chamado sala com topologia quadrada
adicione uma camada chamada terreno ao mapa sala
coloque o bloco "parede" na célula (1, 1) da camada terreno do mapa sala

defina backend como BackendNulo()

Este exemplo não imprime texto no terminal.

O conjunto de exemplos oficiais inclui uma grade de temperatura, um autômato celular e um mapa de ocupação robótica justamente para provar que visualização é um consumidor opcional e não a fundação da API.

API orientada a objetos

Formas como Mundo(...), mundo.criar_entidade(...) e mundo.relacionar(...) continuam válidas. Elas são consideradas superfície avançada e não a forma principal dos templates e tutoriais oficiais quando existe frase Coral equivalente.

Precisões preservadas na linha 1.2

As relações são dirigidas, mas Mundo.caminho e a frase natural de busca consideram ambas as direções por padrão (bidirecional=True). A API avançada aceita bidirecional=falso numa expressão Coral para seguir somente saídas. A implementação atual rejeita entidades externas que tenham apenas o mesmo nome de uma entidade local. para_json exporta o estado genérico do mundo; não é um formato completo de persistência de personagens e combates.

Um mundo reúne entidades e relações. Entidades têm identidade própria: dois objetos com o mesmo nome não são intercambiáveis. A biblioteca recusa relações com objetos externos que apenas repetem o nome de uma entidade registrada.

Geometria compartilhada

Neste modelo, coral.jogos continua 2D, mas colisões de sprites reutilizam as relações geométricas gerais da base espacial. A direção da dependência permanece única: Jogos conhece a infraestrutura espacial; a base espacial não conhece sprites, cenas nem Pygame. O contrato histórico de Jogos também é preservado: sobreposição interior conta como colisão, enquanto apenas encostar pelas bordas não conta.

O exemplo Exemplos/Jogos/01_geometria_compartilhada.coral executa sem janela e sem Pygame. Ele compara dois sprites sobrepostos, um terceiro apenas tangente e usa, no mesmo programa, uma consulta espacial geral sobre posições comuns. A versão equivalente na biblioteca geral fica em Exemplos/Citados/Jogos/04_geometria_compartilhada.coral.

Mouse e tela cheia

A Coral oferece mouse e tela cheia parte do contrato público de coral.jogos. criar_jogo(..., tela_cheia=verdadeiro) permite iniciar no modo de tela cheia pela API avançada, e Jogo pode consultar ou alternar esse estado durante a execução. O comportamento padrão permanece em janela quando a opção é omitida.

A entrada de mouse diferencia estado contínuo de eventos do quadro. posicao_mouse() e botao_mouse_pressionado(...) consultam o estado atual; mouse_clicado(...), mouse_solto(...) e roda_mouse() representam eventos observados no quadro corrente. Essa distinção evita confundir manter um botão pressionado com um novo clique. Os nomes de botão aceitos incluem esquerdo, meio e direito.

No BackendNulo, definir_mouse(...) fixa um estado e programar_mouse(...) descreve quadros determinísticos, permitindo testar interação sem abrir janela. O mesmo backend registra mudanças de tela cheia. A abertura real de janela, a entrada do sistema e o modo de tela cheia continuam dependendo do Pygame CE e do ambiente gráfico.

Folhas de sprites e transformações visuais

A biblioteca oferece folhas de sprites para uso sem janela sem tornar Pygame uma dependência do núcleo. Spritesheet descreve uma folha ou atlas, QuadroSprite representa um recorte imutável, e animações podem consumir esses quadros sem abandonar o formato antigo baseado em caminhos de imagens.

Sprite oferece transformação visual independente da colisão e do estado de coral.mundo: escala uniforme, rotação em graus, espelhamento horizontal e vertical, origem e pivô local. As origens estruturadas reconhecidas são topo_esquerdo, centro e centro_inferior. Um pivô personalizado é informado como (x, y) nas unidades locais anteriores à escala. O ponto escolhido permanece ancorado na posição do sprite enquanto a representação visual é transformada.

A chamada estruturada Jogo.desenhar_imagem(...) aceita os mesmos parâmetros opcionais. Omiti los preserva a semântica anterior. O BackendNulo registra comandos transformados sem abrir arquivos ou janela; o backend Pygame aplica as operações à imagem carregada ou ao quadro recortado. A abertura de janela e o resultado visual físico continuam sujeitos a teste de campo com Pygame CE.

Estas interfaces pertencem à camada avançada e interoperável. Elas foram mantidas como fundação técnica até os gates de contrato, erros e regressão ficarem verdes; só então partes com ganho pedagógico claro começaram a receber frases Coral naturais.

Na implementação atual, a integração com coral.mundo ganha uma ponte visual opcional do lado de coral.jogos. Cena.representar(...) associa uma entidade a um Sprite por atributos de posição explicitamente nomeados, mantendo a entidade como fonte de verdade. A dependência não é invertida: coral.mundo continua sem importar jogos, sprites ou Pygame, de modo que a mesma entidade pode existir em simulações sem janela e em aplicações sem interface.

A biblioteca atual não mantém mais o antigo laboratório versionado de desenvolvimento. O exemplo Exemplos/Citados/Jogos/02_sprites_transformacoes_e_animacao.coral concentra a superfície estável de sprites, transformações e automações em modo sem janela; validações históricas de spritesheets, recortes e estados permanecem na suíte de regressão.

Na implementação atual, uma primeira fatia da superfície natural é promovida para parser/AST: carregue a spritesheet ..., pegue o quadro ..., crie uma animação ..., use o quadro ..., use a animação ... e represente ... com o sprite ... na cena .... Essas frases compilam para a API estrutural já estabilizada e são conhecidas pela semântica, tabela de símbolos, Naturalidade, Ensinar e LSP. Métodos diretos continuam válidos como API avançada, mas a documentação para iniciantes prioriza as frases Coral.

O exemplo Exemplos/Citados/Jogos/02_sprites_transformacoes_e_animacao.coral demonstra a superfície estável de sprites sem janela e sem Pygame CE.

Na implementação atual, as transformações visuais estabilizadas recebem a superfície natural ajuste a escala do sprite ..., gire o sprite ... em ... graus, espelhe o sprite ... e ancore o sprite .... A ancoragem por origem aceita topo esquerdo, centro e centro inferior; selecionar uma origem limpa um pivô personalizado anterior. ancore ... no pivô X e Y volta a definir um ponto local personalizado que prevalece na transformação. O editor e as ferramentas de análise reconhecem essas formas.

O mesmo exemplo demonstra escala, rotação, espelhamento, ancoragem, colisão associada e automação matemática sem janela.

Na implementação atual, o modelo direcional deixa de tratar cima, baixo, esquerda e direita como uma lista estrutural fixa. A base compartilhada passa a ser um conjunto arbitrário de direções nomeadas, cada uma associada a um vetor bidimensional. Duas, quatro e oito direções são apenas predefinições convenientes do mesmo mecanismo. Vetores diagonais são normalizados para preservar a distância efetiva do movimento.

Movimento e apresentação não precisam possuir a mesma quantidade de direções. use movimento em 8 direções no jogador pode ser ligado a uma animação com apenas esquerda e direita por ligue a animação andar ao movimento de jogador no sprite visual. BackendNulo

BackendNulo executa a lógica sem abrir uma janela. Ele existe para testes automatizados, CI, simulações e desenvolvimento em ambientes sem vídeo. Isso permite testar a maior parte da API mesmo sem Pygame CE instalado.

Pygame CE

Pygame CE é o backend gráfico oficial de coral.jogos. A documentação do Pygame CE cobre janela/display, desenho, eventos, teclado, imagens, áudio, tempo e sprites, que são as capacidades sobre as quais a camada Coral é construída.

API avançada

O runtime também pode ser manipulado por classes e métodos (Jogo, Cena, Sprite, jogo.executar(), etc.). Essa camada é válida para extensão da engine e interoperabilidade, mas os templates oficiais priorizam a sintaxe natural Coral quando ela existe.

Instalar a dependência correta

Pygame CE é o backend gráfico oficial. O runtime básico funciona sem ele. Instale Pygame usando o Python da instalação persistente. No Linux, com a pasta padrão:

Construir o primeiro jogo, passo a passo

O arquivo principal.coral do template jogo-2d tem o programa abaixo. Esta versão de estudo executa dois quadros sem janela, para permitir a verificação automática. Para abrir uma janela, retire sem janela da criação do jogo e substitua a última instrução por inicie jogo. Esse modo exige Pygame CE e ambiente gráfico e permanece ativo até o encerramento do jogo.

Código Coral
# Versão de estudo: executa dois quadros sem janela.
de coral.jogos importe AZUL e AMARELO

crie um jogo chamado jogo com largura 800 e altura 450 sem janela
crie uma cena chamada principal
crie um sprite chamado jogador em 100 e 180 com largura 40 e altura 40 e cor AMARELO
adicione jogador à cena principal
mude jogo para a cena principal

quando o jogo jogo atualizar com dt
    se a tecla "direita" estiver pressionada no jogo jogo então
        mova jogador 180 vezes dt para a direita
    fim
    se a tecla "esquerda" estiver pressionada no jogo jogo então
        mova jogador 180 vezes dt para a esquerda
    fim
fim

quando o jogo jogo desenhar
    limpe jogo com AZUL
    desenhe o texto "Use ← e -> para mover" em 20 e 20 no jogo jogo com tamanho 24
fim

execute jogo.executar(max_quadros=2)

Este exemplo não imprime texto no terminal.

  1. A importação disponibiliza as duas cores. A criação do jogo define dimensões de 800 por 450 pixels, mesmo neste modo sem janela.
  2. A cena reúne o conteúdo visível. O sprite começa em x=100 e y=180, com largura e altura de 40 pixels. Adicioná lo à cena e selecionar a cena são operações separadas.
  3. O evento de atualização consulta o estado das setas a cada quadro. 180 vezes dt desloca o jogador de acordo com o tempo decorrido. As coordenadas de tela crescem para a direita e para baixo.
  4. O evento de desenho limpa o fundo e escreve a instrução. Em seguida, o ciclo desenha a cena, incluindo seus sprites. Desenho deve ocorrer novamente a cada quadro.
  5. execute jogo.executar(max_quadros=2) limita o estudo a dois quadros. No modo com janela, inicie jogo entra no ciclo de execução até o encerramento. Para começar, altere a cor, a velocidade e a posição inicial, uma mudança por vez.

O programa não impede o jogador de sair da janela: limites e regras de colisão pertencem à lógica do jogo. Também não carrega imagens ou sons. Acrescente esses recursos depois de conferir o movimento básico.

Referência prática dos objetos gráficos

A superfície natural é a primeira opção para iniciar jogos. As assinaturas abaixo documentam a API de componentes para integração e comportamentos mais específicos. objeto.metodo(...) usa a instância que você criou. self não é passado nas chamadas.

Para usar uma câmera, atribua sua instância a cena.camera. A cena atualiza a câmera e transforma as posições ao desenhar. Para animar, atribua uma Animacao a sprite.animacao; seus quadros representam caminhos de imagens. A atribuição de sprite.velocidade_x dispensa movimentá lo manualmente por essa mesma velocidade no callback: fazer ambos soma os dois deslocamentos.

Callbacks do jogo recebem (jogo), exceto atualização, que recebe (jogo, dt). Callbacks da cena recebem (jogo, cena); atualização da cena recebe (jogo, cena, dt). Registre funções com quando_iniciar, quando_atualizar, quando_desenhar e quando_encerrar no jogo, ou com os registradores correspondentes de entrada, saída, atualização e desenho na cena. Uma assinatura incompatível causa erro na execução.

37. Procedural

Objetivo de leitura

Produzir dados reproduzíveis com sementes, campos e receitas.

Antes de começar

Conheça funções, coleções e sementes.

Uma operação procedural produz dados a partir de uma regra. Quando preservamos a receita e a semente, podemos repetir o resultado sob o mesmo contrato. Isso é útil para mapas, simulações e dados sintéticos.

Semente, campo e receita

coral.procedural é uma biblioteca geral de geração reproduzível. Ela não depende de Jogos, RPG nem interface gráfica. Semente, GeradorProcedural, SequenciaProcedural e CampoProcedural permitem derivar domínios independentes, consultar valores por chave ou coordenada sem depender da ordem de consultas anteriores, compor campos e distribuir pontos sob limites finitos. Na 1.6.15, pesos inválidos recebem diagnóstico explícito, campos declaram dimensionalidade e intervalos conhecidos, e a ordem de operações não comutativas permanece observável.

ReceitaProcedural, receita_procedural, reconstruir_receita e diagnosticar_custo_receita formam a camada declarativa portátil. As receitas suportadas registram algoritmo, versão, semente e parâmetros e podem ser preservadas por coral.persistencia. Callbacks não entram na forma portátil. Reconstrução e materializações grandes possuem limites de custo explícitos, sem esconder trabalho ou alocação potencialmente desproporcional.

O módulo serve a simulações, mapas, ecologia, dados sintéticos e outros domínios. Jogos e Laboratório podem consumi lo, mas não são sua finalidade obrigatória.

Na 1.6.17, amostrar_campo e matriz_campo tornam a observação do campo uma operação explícita e limitada. anotar_pontos combina distribuições espaciais com grandezas como altitude, umidade ou risco. proveniencia_procedural fornece metadados portáteis sem afirmar que um callback arbitrário pode ser reconstruído.

A ponte com Jogos vive no consumidor: receitas de distribuir_pontos podem preencher cenas com sprites reprodutíveis e campos podem escrever valores em sprite.dados, sem abrir janela. A ponte com Laboratório trata receita e semente procedural como parte do desenho experimental, separadas da semente usada pelo próprio protocolo de medição. planejar_experimento_procedural calcula execuções e custo máximo antes de reconstruir a receita; executar_experimento_procedural preserva a receita base e as sementes nos metadados do resultado.

Procedural em jogos e pesquisa

A fundação procedural permite que o mesmo processo determinístico possa ser usado na construção de cenários de jogo e em experimentos reproduzíveis.

A regra central continua simples: uma semente e uma receita descrevem como produzir algo. Jogos decide como apresentar esse resultado. Laboratório decide como medir e comparar execuções. Procedural não precisa conhecer nenhum dos dois.

Usando pontos em uma cena

Uma receita de distribuição pode ser passada a sprites_de_receita ou popular_cena_procedural. O adaptador cria sprites nas mesmas posições sempre que a receita, a semente e a versão do contrato forem as mesmas. Nenhuma janela é aberta por essa conversão.

Campos procedurais podem ser aplicados aos sprites depois. O valor fica em sprite.dados, permitindo que um programa use, por exemplo, relevo para escolher aparência, fertilidade para crescimento ou perigo para regras de encontro.

Medindo uma receita

planejar_experimento_procedural combina sementes, parâmetros e repetições sem executar a receita. Além do número de execuções, ele mostra o custo máximo declarado. Isso é especialmente útil quando uma distribuição possui muitas tentativas possíveis.

executar_experimento_procedural reconstrói a receita para cada semente e entrega o produto à função estudada. Cada medição preserva a semente procedural, e o resultado guarda a receita base nos metadados. Assim é possível comparar diferentes sementes sem perder de vista exatamente qual processo gerou cada observação.

Enviando campos a Gráficos

amostrar_campo cria registros gerais. Eles podem ser enviados a series_de_registros. matriz_campo cria uma matriz 2D que pode ser enviada diretamente a mapa_calor. A integração não exige que Gráficos conheça CampoProcedural.

Quando usar cada caminho

Use amostrar_campo quando você precisa preservar coordenadas individuais. Use matriz_campo para grades 2D finitas. Use anotar_pontos quando uma distribuição espacial precisa receber grandezas ambientais. Use as funções de Jogos quando o resultado vai virar objeto visual. Use as funções de Laboratório quando sementes ou parâmetros precisam ser comparados sob um protocolo experimental explícito.

38. Computação numérica e científica

Objetivo de leitura

Escolher operações numéricas e reconhecer seus requisitos e limites de interpretação.

Antes de começar

Conheça matemática e coleções; estatística básica ajuda nas seções avançadas.

coral.numerico reúne operações sobre séries, vetores e matrizes. Comece escolhendo o cálculo necessário e conferindo o formato dos dados. As fichas deste capítulo apresentam as assinaturas e exemplos completos; as seções de estatística avançada podem ser consultadas depois.

Uma série é uma sequência de valores. Uma matriz organiza valores em linhas e colunas. Dados finitos excluem valores como infinito e NaN, que representa um resultado numérico indefinido. Quando uma operação exige NumPy, o pacote precisa estar instalado; importar o módulo não carrega essa dependência antecipadamente.

Validar os dados antes de calcular

A API normaliza erros públicos relevantes como ErroNumerico, valida matrizes, estatísticas, intervalos e reduções vazias e evita vazar detalhes acidentais do backend NumPy para a superfície Coral. As estatísticas numéricas rejeitam dados ausentes, NaN e infinito com diagnóstico público em português. selecionar_coluna permite escolher explicitamente se registros ausentes geram erro ou são ignorados. Percentis e quartis usam interpolação linear declarada; correlação rejeita variância zero; moda preserva empates em vez de inventar uma única categoria vencedora.

A mesma política cobre álgebra linear e geometria 3D. norma e normalizar trabalham com vetores finitos; posto e minimos_quadrados validam formas; produto_vetorial é restrito a três dimensões. rotacionar3 usa a fórmula de Rodrigues e ângulo em radianos. transformar_ponto3 recebe uma matriz afim homogênea 4 × 4 e usa vetor coluna, mantendo a coordenada homogênea apenas como detalhe interno.

Nas operações estatísticas, erro_padrao usa desvio padrão amostral e exige pelo menos duas observações. assimetria e curtose usam momentos centrais padronizados e rejeitam variância zero; curtose é devolvida em excesso. matriz_covariancia interpreta linhas como observações e colunas como variáveis e matriz_correlacao rejeita colunas constantes. regressao_linear devolve inclinação, intercepto, resíduos, R² e quantidade de observações.

intervalo_bootstrap implementa intervalo percentil por reamostragem e teste_permutacao implementa teste bilateral por diferença da estatística escolhida pelo programa. Ambos usam um gerador local por semente, registram repetição e custo estimado e recusam trabalho acima do limite interno. Intervalos e valores p são resultados numéricos; a biblioteca não os transforma automaticamente em causalidade, superioridade ou significância substantiva.

A camada tridimensional oferece matriz_rotacao3, matriz_translacao3, matriz_escala3, compor_transformacoes3 e transformar_vetor3. As relações ponto plano são cobertas por distancia_ponto_plano3, projetar_ponto_plano3 e intersecao_reta_plano3. coordenadas_esfericas3 e ponto_de_esfericas3 fazem a conversão explícita entre representações, enquanto area_triangulo3 e volume_tetraedro3 tratam medidas geométricas sem recorrer ao backend gráfico.

Estatística avançada em coral.numerico

As operações desta seção fazem parte do runtime 1.7.6.

A implementação permanece em coral.numerico, com NumPy opcional na importação e exigido somente quando uma operação numérica que dele depende é chamada. SciPy não é dependência desta versão.

Medidas de forma e incerteza

erro_padrao(valores) calcula o erro padrão da média usando o desvio padrão amostral, com divisor n - 1, e exige ao menos duas observações finitas.

assimetria(valores) calcula o terceiro momento central padronizado sem correção de viés amostral. curtose(valores) calcula o quarto momento padronizado e devolve curtose em excesso, subtraindo 3. As duas operações rejeitam variância zero porque o denominador seria indefinido.

Matrizes de associação

matriz_covariancia(dados, populacional=False) interpreta cada linha como uma observação e cada coluna como uma variável. O padrão é amostral; populacional=True troca o divisor para n.

matriz_correlacao(dados) devolve a matriz de correlação de Pearson para as colunas observadas conjuntamente. Colunas constantes são rejeitadas explicitamente. As rotinas usam centralização escalada para reduzir transbordamentos intermediários evitáveis.

Regressão linear

regressao_linear(x, y) ajusta y = intercepto + inclinacao * x por mínimos quadrados simples. O retorno é ResultadoRegressaoLinear e inclui:

  • inclinacao;
  • intercepto;
  • residuos;
  • r_quadrado;
  • quantidade.

As séries precisam ter o mesmo comprimento, conter ao menos duas observações e usar somente valores finitos. Uma série x constante não identifica uma inclinação e produz ErroNumerico. Uma série y constante é válida e resulta em inclinação zero e R² igual a 1 para o ajuste constante exato.

Bootstrap

intervalo_bootstrap(valores, estatistica, confianca, repeticoes, semente) usa reamostragem com reposição e devolve ResultadoBootstrap.

O método disponível nesta edição é o intervalo percentil. A função estatística é fornecida pelo programa, deve ser chamável e precisa produzir um número real finito. A semente é inteira e alimenta uma instância local de random.Random, portanto o gerador aleatório global do programa não é modificado.

O resultado registra estimativa observada, limites inferior e superior, confiança, repetições, semente, tamanho da amostra, custo estimado e o identificador bootstrap_percentil.

Teste de permutação

teste_permutacao(a, b, estatistica, repeticoes, semente) estima bilateralmente a probabilidade de obter uma diferença de magnitude pelo menos igual à observada quando os rótulos dos dois grupos são permutáveis sob a hipótese nula.

O valor p usa a correção (extremos + 1) / (repeticoes + 1), evitando zero artificial em uma simulação finita. O resultado registra diferença observada, valor p, tamanhos dos grupos, repetições, semente, custo estimado e o identificador permutacao_bilateral.

Limites e interpretação

Bootstrap e permutação possuem limite interno de 5 000 000 de observações processadas por chamada para impedir custos acidentais muito grandes. O limite é validado antes de iniciar a repetição.

Intervalos e valores p são resultados de métodos declarados, não conclusões automáticas. A Coral não afirma causalidade, não classifica um efeito como importante e não transforma um limiar arbitrário em verdade científica. A interpretação continua sob responsabilidade do programa e do contexto da análise.

Generalidade

As rotinas aceitam séries e matrizes comuns e não dependem de coral.laboratorio. Resultados de experimentos podem ser convertidos em séries pelo programa, mas as fórmulas não assumem uma origem específica para os dados.

Compor gráficos e representar incerteza

A superfície gráfica continua geral. Ela recebe listas, matrizes e séries comuns sem exigir coral.laboratorio. O adaptador de experimentos é acionado apenas quando grafico_experimento é chamado.

mapa_calor(matriz) representa valores já calculados em uma matriz retangular. mapa_correlacao(dados) delega o cálculo de Pearson a coral.numerico.matriz_correlacao e apenas apresenta o resultado. Assim, a definição estatística continua pertencendo ao módulo numérico.

barras_erro(x, y, erros) aceita incertezas simétricas ou pares inferior e superior. faixa_incerteza(x, centro, inferior, superior) recebe limites absolutos. A faixa não é chamada automaticamente de intervalo de confiança porque seu significado vem do método que produziu os limites.

grafico_experimento(resultado, eixo_x, metrica) converte medições bem sucedidas de um ResultadoExperimento para a mesma Serie2D usada pelos gráficos gerais. Nome do experimento, sementes e protocolo de medição ficam registrados na proveniência da especificação.

painel(graficos, colunas) compõe várias especificações sem alterar seus dados ou escalas. para_svg continua funcionando apenas com a biblioteca padrão e também aceita painéis.

salvar(grafico, caminho) reconhece .svg, .png e .pdf. SVG continua sendo o backend básico e autossuficiente. PNG e PDF carregam Matplotlib somente quando solicitados. Se o backend opcional não estiver instalado, a Coral devolve erro orientando a instalação em vez de falhar durante import coral.graficos.

A importação de coral.graficos não carrega Matplotlib, Plotly, NumPy nem Laboratório antecipadamente. HTML interativo usa Plotly opcional, descrito adiante.

Gráficos 3D

coral.graficos passa a aceitar especificações tridimensionais sem transformar visualização em cálculo geométrico. coral.numerico continua responsável por vetores, transformações, planos, coordenadas esféricas, áreas e volumes. Gráficos recebe coordenadas já definidas e as apresenta.

Pontos e trajetórias

dispersao3d(x, y, z, nome=None) cria uma coleção de pontos tridimensionais. trajetoria3d(x, y, z, nome=None) preserva a mesma sequência de coordenadas e apenas indica que os pontos devem ser ligados na ordem fornecida.

Os três eixos precisam ter o mesmo comprimento. Valores ausentes, NaN e infinito são rejeitados. As coleções de entrada não são modificadas nem reordenadas.

Superfícies

superficie3d(x, y, z, nome=None) representa uma grade retangular explícita. Há duas formas aceitas.

Quando x e y são eixos unidimensionais, z deve possuir len(y) linhas e len(x) colunas. Quando x e y são grades bidimensionais, as três grades precisam ter exatamente a mesma forma.

A função não interpola pontos ausentes, não corrige grades irregulares e não inventa valores entre amostras. Uma superfície descreve somente os pontos presentes na grade fornecida.

Configuração dos eixos

configurar aceita dois ou três rótulos e unidades. Em gráficos 3D, a forma eixos=("x", "y", "z") e unidades=("m", "m", "m") também configura o terceiro eixo. Mapeamentos podem usar as chaves x, y e z.

Renderização estática

Criar dispersao3d, trajetoria3d ou superficie3d não importa Matplotlib, não abre janela e não escolhe uma projeção escondida. para_svg continua sendo o renderizador próprio da Coral para especificações 2D e, por isso, rejeita gráficos 3D em vez de achatá los silenciosamente.

salvar usa Matplotlib somente quando uma renderização 3D é solicitada. Gráficos 3D podem ser salvos em SVG, PNG ou PDF quando o backend opcional está instalado. A importação de coral.graficos permanece independente de Matplotlib.

Fronteira de responsabilidade

A câmera e a projeção visual usadas pelo backend servem apenas à apresentação. As coordenadas originais guardadas em Serie3D e Superficie3D permanecem inalteradas. Operações geométricas como rotação, transformação afim, projeção sobre plano e interseção reta plano pertencem a coral.numerico.

A linha 1.6.x não possui uma superfície pública dedicada a espaço 4D. A decisão da 1.6.12 concentra a evolução espacial da Coral em 3D.

Consultar os gráficos interativos

coral.graficos pode transformar as especificações científicas já existentes em HTML interativo autossuficiente. Plotly continua opcional e só é carregado quando a capacidade interativa é solicitada.

HTML local e offline

para_html(grafico) devolve um documento HTML completo em memória. salvar_html(grafico, caminho) grava o mesmo documento de forma atômica. O JavaScript necessário é incorporado no próprio arquivo, portanto a visualização não depende de CDN nem de conexão com a internet.

O HTML preserva os valores já presentes na especificação. O backend não recalcula estatística, não interpola superfícies, não suaviza trajetórias e não reduz coleções silenciosamente.

Exploração explícita

explorar(grafico) cria uma prévia local e pede ao navegador do sistema que a abra. A operação só acontece quando chamada explicitamente. Criar um gráfico ou importar coral.graficos não abre janela, navegador, servidor ou conexão.

Em sessão sem interface gráfica, explorar produz um diagnóstico orientando o uso de salvar_html. Nenhuma porta é aberta como alternativa implícita.

Painéis 2D e 3D

Painéis podem combinar gráficos 2D e 3D na mesma saída interativa. Cada subgráfico mantém título, eixos, unidades e tipo de cena. Séries de grafico_experimento continuam séries comuns depois da adaptação e preservam avisos e proveniência no texto acessível do documento.

Para 3D, dispersões, trajetórias e superfícies preservam as coordenadas originais. Rotação, zoom e posição da câmera pertencem apenas à apresentação.

Limites e amostragem

A exportação HTML possui um limite de observações ou células para evitar materialização acidental de documentos desproporcionais. Ao exceder o limite, a operação falha antes da renderização e explica as alternativas disponíveis.

amostrar_grafico(grafico, max_pontos) oferece uma redução uniforme explícita apenas para linhas, dispersões e séries 3D simples. A especificação devolvida registra a quantidade original, a quantidade mantida e um aviso de amostragem. A função nunca é chamada automaticamente por para_html.

Mapas, superfícies, caixas, barras e faixas não são reduzidos automaticamente porque uma seleção genérica poderia alterar sua semântica. Nesses casos, o programa deve preparar uma representação menor antes de construir o gráfico.

Privacidade e acessibilidade

O HTML autossuficiente contém os dados do gráfico incorporados. A página inclui um aviso visível lembrando que dados sensíveis devem ser revisados antes de compartilhar o arquivo.

A visualização recebe papel de imagem e descrição acessível. texto_alternativo, avisos e proveniência participam dessa descrição. Em painéis, as descrições dos filhos também são preservadas.

Integração com servidor local

coral.web.servidor.resposta_grafico(grafico) converte explicitamente um gráfico em RespostaServidorHTTP. A função não cria nem inicia servidor. Ela apenas prepara a resposta HTML e usa Cache-Control: no-store por padrão porque o documento contém os próprios dados.

Para publicar localmente, o programa cria um servidor, registra uma rota que devolve resposta_grafico e então chama iniciar() de forma explícita. Assim Gráficos não passa a depender de Web e Web não inicia rede durante a adaptação.

Dependência opcional

Plotly 6.0 ou superior pertence ao componente opcional graficos_interativos. A ausência do pacote não impede import coral.graficos, SVG, PNG, PDF ou as especificações 2D e 3D. O erro aparece apenas ao solicitar HTML interativo.

40. Web

Objetivo de leitura

Distinguir HTML local, cliente HTTP e servidor HTTP.

Antes de começar

Conheça textos, funções e tratamento de erros.

A base Web separa geração local de HTML e URLs, cliente HTTP e servidor HTTP. Escolha apenas a capacidade que sua aplicação precisa.

Montar HTML e manipular URLs

coral.web.html e coral.web.url formam a base Web local da Coral. Nesta versão as duas superfícies trabalham somente em memória: importar os módulos não abre conexão, porta, navegador ou janela. As requisições HTTP usam o módulo próprio, apresentado mais adiante.

HTML seguro por padrão

escapar_texto(valor) codifica texto para o conteúdo de elementos. escapar_atributo(valor) codifica texto para atributos entre aspas. Escape não transforma uma URL perigosa em URL segura, por isso atributos de URL são validados separadamente.

elemento(nome, atributos, filhos) cria um ElementoHTML imutável. Nomes de elemento e atributo são validados, atributos de evento inline como onclick são recusados e esquemas executáveis como javascript: não são aceitos em href, src, action e atributos equivalentes. Texto comum em filhos nunca é interpretado como marcação confiável.

fragmento(filhos) agrupa nós sem inserir um contêiner extra. documento(titulo, corpo, idioma) cria um DocumentoHTML completo com UTF 8 e idioma declarado. renderizar(no) produz a serialização em memória e não escreve arquivo.

Tabelas de registros gerais

tabela(registros, colunas) aceita mapeamentos ou objetos com atributos. As colunas são explícitas e mantêm a ordem fornecida. Um campo ausente produz erro em vez de desaparecer silenciosamente, e o valor de cada célula continua sujeito ao escape de texto. Isso permite apresentar dados comuns e, por conversão explícita, dados produzidos por outros módulos sem importar coral.laboratorio.

Consultas e URLs

codificar_consulta(parametros) aceita mapeamento ou sequência ordenada de pares. Chaves repetidas são preservadas e o texto usa UTF 8. ler_consulta(texto) devolve os pares na mesma ordem, preservando valores vazios e duplicatas.

decompor(endereco) exige esquema explícito e devolve EnderecoURL, com esquema, autoridade, host, porta, caminho, consulta e fragmento. A propriedade parametros decodifica a consulta sem perder chaves repetidas. juntar(base, referencia) resolve uma referência relativa contra uma base usando apenas regras textuais. Nenhuma dessas operações resolve DNS ou acessa a rede.

Exemplo

O exemplo Exemplos/Citados/Web/01_html_e_url.coral monta um documento com tabela, escapa conteúdo potencialmente ambíguo e prepara uma URL com consulta repetida. Ele pode ser compilado e executado sem conexão de rede.

Escolher o módulo adequado

HTML e URL trabalham em memória. Para acessar um endereço, use coral.web.http; para atender requisições locais, use coral.web.servidor. Montar uma página não a hospeda automaticamente.

Fazer uma requisição HTTP

coral.web.http é o primeiro cliente HTTP geral da Coral. Importar o módulo não abre conexão, não inicia servidor e não consulta recursos externos. A rede só é usada quando requisitar, obter ou enviar é chamada. O módulo não depende de coral.laboratorio.

Resposta preservada em bytes

RespostaHTTP preserva status, cabecalhos, corpo_bytes, url, metodo e a quantidade de redirecionamentos. A propriedade sucesso apenas indica status entre 200 e 299. Respostas 3xx, 4xx e 5xx continuam inspecionáveis e não são transformadas automaticamente em erro de transporte.

texto(codificacao) decodifica o corpo sob demanda. O corpo recebido nunca é convertido silenciosamente em texto. json() interpreta JSON sob demanda e usa ErroFormato para conteúdo inválido, separando erro de formato de falha de transporte.

Requisições

requisitar(metodo, url, cabecalhos, corpo, tempo_limite) é a operação geral. obter(url, ...) é o atalho para GET e enviar(url, corpo, ...) é o atalho para POST. Texto enviado exige codificacao_corpo explícita; bytes são enviados sem conversão.

O cliente aceita somente URLs http e https, rejeita credenciais embutidas e valida nomes e valores de cabeçalhos antes de montar a requisição. A execução usa a biblioteca padrão e não requer pacote externo.

Timeout e limite de resposta

Toda requisição tem tempo_limite finito. limite_resposta limita o corpo materializado em memória; se Content-Length já declara tamanho acima do teto ou se a leitura excede o limite, a operação falha com ErroLimiteHTTP em vez de truncar silenciosamente.

Esses limites controlam o cliente, não substituem políticas da aplicação. O programa ainda decide quais hosts pode acessar, que dados envia e que respostas considera confiáveis.

Redirecionamentos

GET, HEAD e OPTIONS seguem redirecionamentos por padrão, com max_redirecionamentos finito. Métodos com potencial de efeito, como POST, não repetem a requisição após redirecionamento sem seguir_redirecionamentos=true explícito. Apenas destinos http e https podem ser seguidos.

Formulários

codificar_formulario(campos) produz application/x-www-form-urlencoded em bytes ASCII com valores codificados em UTF 8. Sequências de pares preservam ordem e chaves repetidas. Multipart, upload de arquivos, cookies persistentes e autenticação automática não fazem parte desta base.

TLS e proxy

HTTPS usa ssl.create_default_context() quando nenhum contexto_tls é fornecido. Isso mantém verificação de certificado e de hostname habilitadas por padrão. Um SSLContext explícito pode ser passado por aplicações que realmente precisam controlar a política TLS.

proxy é explícito. Quando não é fornecido, o cliente não depende de uma camada Coral de proxy. Quando configurado, aceita uma URL textual para HTTP e HTTPS ou um mapeamento por esquema.

Exemplo local

Exemplos/Citados/Web/02_cliente_http_loopback.coral recebe a URL de um servidor local efêmero como argumento do programa, faz GET de JSON e POST de formulário e inspeciona status e corpo. O gate da release executa esse fluxo somente em loopback, sem serviço externo.

Limites do cliente

O cliente não oferece upload multipart, cookies persistentes, cache ou autenticação automática. O servidor é um módulo separado. HTML e URL continuam utilizáveis sem conexão.

Servidor HTTP local da Coral

coral.web.servidor oferece um servidor pequeno para desenvolvimento, demonstrações e testes locais. Importar o módulo não abre porta. criar_servidor() apenas cria a configuração; a escuta começa com iniciar() ou ao usar o objeto em um bloco de contexto.

Por padrão, o servidor usa 127.0.0.1 e porta 0. A porta zero pede ao sistema uma porta efêmera livre. Exposição fora do loopback exige permitir_externo=True, portanto não acontece por acidente.

Rotas literais

adicionar_rota é o método ServidorHTTP.adicionar_rota(metodo, caminho, tratador) e registra uma combinação literal como GET /estado. A 1.6.9 não interpreta parâmetros de rota, curingas ou expressões. O tratador recebe RequisicaoHTTP e deve retornar RespostaServidorHTTP.

A requisição preserva metodo, caminho, consulta, cabecalhos, corpo_bytes e cliente. texto(), json() e formulario() interpretam o corpo somente quando o programa pede. Consultas e formulários preservam ordem e chaves repetidas.

Respostas

Use resposta_bytes, resposta_texto, resposta_html ou resposta_json. HTML reutiliza a serialização segura de coral.web.html; texto comum não vira marcação por acidente. JSON recusa valores que exigiriam conversão silenciosa e não aceita NaN como JSON válido.

Limite de corpo

limite_corpo é aplicado a Content-Length antes de o tratador ser chamado. Corpos acima do limite recebem status 413. tempo_limite_corpo impede que uma leitura parcial mantenha a conexão indefinidamente. O servidor básico não implementa corpo de requisição com Transfer-Encoding.

Arquivos sob raiz declarada

Ao criar o servidor, raiz_arquivos pode apontar para uma pasta explícita. adicionar_arquivo associa um arquivo relativo a uma rota literal. Caminhos absolutos, .. que saiam da raiz e links simbólicos que saiam da raiz declarada são recusados. limite_arquivo impede leitura acidental de arquivos acima do teto escolhido.

Encerramento

encerrar() faz shutdown, fecha o socket e aguarda a thread de atendimento. A chamada é idempotente. Usar com servidor: também encerra o serviço ao sair do bloco.

O servidor é uma ferramenta de desenvolvimento local. Ele não é um servidor de produção, não oferece TLS de servidor, autenticação, balanceamento, HTTP/2 ou gestão de processos. O cliente HTTP da Coral permanece em coral.web.http e continua independente do servidor.

Resposta de gráfico interativo

Na 1.6.13, resposta_grafico(grafico) adapta uma especificação de coral.graficos para uma RespostaServidorHTTP com HTML interativo autossuficiente. A adaptação é explícita e não inicia servidor, não abre porta e não acessa recursos remotos.

A resposta usa Cache-Control: no-store por padrão porque o HTML contém os dados da figura. O programa continua responsável por criar o servidor, registrar a rota e chamar iniciar() quando realmente quiser publicar a página no loopback.

41. Sistema e hardware

Objetivo de leitura

Consultar capacidades do sistema e reconhecer limites de testes simulados.

Antes de começar

Conheça funções e tratamento de erros.

Um script pode consultar o ambiente em que está sendo executado e, quando necessário, iniciar outro programa. São ações diferentes: descobrir se um executável existe não significa executá lo.

Comece pelas operações de consulta nas fichas. Depois estude captura de saída, prazo de execução e hardware. Um teste simulado verifica a lógica, mas o comportamento de uma placa física precisa ser observado no equipamento.

Inspeção e execução

coral.sistema separa inspeção de capacidade de execução. localizar_programa e programa_disponivel consultam executáveis sem iniciá los; quantidade_processadores, pasta_temporaria e terminal_interativo descrevem capacidades do hospedeiro sem prometer recursos efetivos sob quotas. ambiente_selecionado copia apenas nomes explícitos e variavel_ambiente_obrigatoria falha sem incluir valores em diagnósticos. argumentos_programa expõe somente os argumentos do programa Coral, enquanto caminho_executavel identifica o executável que hospeda o runtime.

executar_comando continua sem shell implícito e agora aceita codificacao, política explícita de erros_decodificacao e limite_saida_bytes. O limite é aplicado enquanto stdout e stderr são drenados, e saida_truncada e erro_truncado registram descarte sem transformar truncamento em falha. Timeout tem prioridade sobre código de saída. ResultadoComando preserva seus campos históricos e acrescenta leituras por linhas, codigo_saida, tempo_decorrido e exigir_sucesso, que produz ComandoFalhou preservando o resultado completo.

Hardware e serial

Inventário de hardware degrada de forma previsível quando dependências opcionais não estão instaladas. A serial possui um backend simulado determinístico usado por contratos e testes. Comunicação com Arduino ou ESP32 físicos continua uma evidência de campo separada e não é declarada aprovada por simulação.

Coral Sistema e processos

coral.sistema reúne informações portáteis do processo Coral e operações explícitas sobre programas do sistema operacional. A biblioteca não substitui coral.hardware: ela descreve capacidades úteis para scripts, ferramentas, automação e aplicações, sem tentar inventariar profundamente CPU, memória ou dispositivos.

Consultar capacidades

localizar_programa(nome) resolve um executável usando o ambiente corrente e devolve seu caminho ou nulo. programa_disponivel(nome) usa a mesma resolução e apenas informa se o programa pode ser encontrado. Nenhuma das duas funções inicia o executável.

quantidade_processadores() devolve a quantidade lógica observada pelo runtime ou nulo quando o hospedeiro não informa esse valor. O número não deve ser interpretado como garantia de capacidade efetiva quando o processo estiver sob quotas, contêineres ou outras restrições.

pasta_temporaria() informa a pasta temporária configurada sem criar arquivos. terminal_interativo(canal) aceita entrada, saida ou erro e informa se o fluxo está associado a um terminal.

Ambiente

ambiente_selecionado(nomes) copia somente as variáveis explicitamente pedidas e omite as ausentes. O resultado é uma nova estrutura, portanto alterá lo não modifica o ambiente do processo.

variavel_ambiente_obrigatoria(nome) devolve a variável solicitada ou produz ErroSistema quando ela não existir. A mensagem de erro informa o nome, mas não inclui valor secreto.

Programa Coral e executável

argumentos_programa() devolve uma cópia dos argumentos fornecidos ao programa Coral. Ao usar o runtime pela linha de comando, separe esses argumentos com --:

Referência para leitura
python coral.pyz meu_programa.coral -- entrada.txt modo-seguro

Nesse caso o programa recebe entrada.txt e modo-seguro; opções internas do interpretador Coral não aparecem na lista.

caminho_executavel() informa o executável que hospeda o runtime, normalmente o Python usado para iniciar o PYZ. processo_atual() informa separadamente o executável, o programa ou PYZ corrente, os argumentos e a pasta atual.

ResultadoComando

Além dos campos históricos codigo, saida, erro e duracao_segundos, um resultado oferece:

  • linhas_saida() e linhas_erro() para leitura por linhas sem alterar o texto original;
  • codigo_saida() como leitura natural de codigo;
  • tempo_decorrido() como leitura natural de duracao_segundos;
  • exigir_sucesso() que devolve o próprio resultado quando o código é zero e produz ComandoFalhou caso contrário, preservando o resultado e o stderr.

Codificação e captura limitada

executar_comando continua executando sem shell. codificacao escolhe a codificação textual e erros_decodificacao aceita estrito, substituir ou ignorar. O padrão é estrito, preservando o comportamento histórico de falhar quando bytes inválidos não podem ser decodificados.

limite_saida_bytes limita separadamente a quantidade mantida em memória para stdout e stderr. O runtime aplica o teto enquanto lê os fluxos e continua drenando o excedente, evitando que um processo de saída contínua bloqueie apenas porque o conteúdo deixou de ser armazenado. saida_truncada e erro_truncado registram se houve descarte.

Timeout tem prioridade: quando o prazo termina, a Coral encerra o grupo de processos quando a plataforma oferece esse mecanismo e produz TempoLimiteExcedido. Truncamento não transforma código de saída zero em falha. Código não zero continua disponível em ResultadoComando e só vira exceção quando exigir_sucesso() é chamado.

Limites

A biblioteca não executa comandos por meio de shell implicitamente, não interpreta metacaracteres, não estima memória livre e não promete que a quantidade de processadores represente recursos realmente disponíveis sob quotas. Arquivos continuam sob responsabilidade de coral.arquivos.

42. Laboratório

Objetivo de leitura

Planejar, registrar e comparar execuções de um experimento.

Antes de começar

Conheça funções, sementes e medições.

Um experimento executa uma operação sob configurações conhecidas e registra medições. Antes de executar, decida quais parâmetros variar, quantas repetições fazer e o que medir. Duas configurações com três repetições produzem seis execuções.

O planejamento ajuda a perceber o custo antes de iniciar. Depois, preserve resultados e contexto para repetir o procedimento e comparar as medições.

Da configuração ao resultado

Experimentos aceitam repetições, parâmetros, sementes e métricas. A implementação preserva os estados aleatórios globais do chamador e não encerra um tracemalloc que já estivesse ativo antes do experimento. Na 1.6.10, planejar_experimento calcula dimensões, combinações e execuções previstas antes da execução; selecionar_medicoes filtra resultados sem alterar o original; e resumir_por_parametro apresenta contagens, falhas, tempos e memória por cenário.

validar_resultado produz diagnósticos estruturados antes de persistir ou comparar. O JSON completo usa coral.laboratorio.resultado/1, esquema 1, e carregar_resultado_json reconstrói tipos portáteis e reconhece explicitamente o formato histórico conhecido até a 1.6.9. CSV e Markdown continuam formatos de relatório, enquanto JSON é a representação recuperável. comparar_experimentos descreve diferenças de configuração, sucessos, tempo e memória usando b - a, mas não calcula significância estatística, causalidade nem superioridade geral.

Na 1.6.17, receitas procedurais podem ser planejadas e executadas como fator experimental. O plano registra quantidade de sementes, grade, repetições e custo preventivo. Cada medição preserva semente_procedural, enquanto o resultado guarda a receita base em metadados. Esse mecanismo mede configurações; ele não escolhe automaticamente a melhor semente nem transforma diferenças descritivas em conclusão científica.

Organizar um experimento

coral.laboratorio permite planejar, executar, filtrar, resumir, persistir e comparar experimentos reproduzíveis. O módulo registra e descreve resultados; a inferência estatística exige métodos próprios.

Planejar antes de executar

planejar_experimento(parametros, repeticoes=1, limite=None) calcula dimensões, combinações e execuções previstas sem construir toda a grade cartesiana. Quando limite é informado, o plano registra se o total o excede e em quanto. A função nunca executa o código estudado.

Selecionar e resumir medições

selecionar_medicoes(resultado, criterio) aceita uma função de decisão ou um mapeamento de igualdade. Use parametros.nome e metricas.nome para tornar a origem de uma chave explícita. A seleção preserva a ordem original e não altera o resultado.

resumir_por_parametro(resultado, nome) agrupa medições pelo valor do parâmetro e informa execuções, sucessos, falhas, tempo médio, tempo mediano e médias de memória. A ordem dos grupos segue a primeira aparição no resultado.

Validar, salvar e reabrir

validar_resultado(resultado) devolve diagnósticos estruturados para estrutura e portabilidade. JSONs novos usam o contrato coral.laboratorio.resultado/1 e esquema 1. carregar_resultado_json(caminho) restaura resultados desse contrato e reconhece explicitamente o formato histórico conhecido até a 1.6.9; contratos ou esquemas desconhecidos são recusados. Valores portáteis, incluindo bytes, são reconstruídos em vez de convertidos silenciosamente para texto.

CSV e Markdown continuam exportações de leitura e análise externa. O JSON versionado é a representação completa destinada à recuperação de um ResultadoExperimento.

Comparar experimentos

comparar_experimentos(a, b) apresenta diferenças de configuração, quantidade de execuções, sucessos, falhas, tempos e memória. Diferenças numéricas são expressas como b - a. A função é deliberadamente descritiva: não calcula valor p, intervalo de confiança, causalidade nem superioridade geral. Para percentis, correlação ou outras operações numéricas, selecione as medições desejadas e use coral.numerico.

Superfície principal

ResultadoExperimento.resumo() continua sendo a visão geral. As operações novas complementam essa visão: planejar_experimento, selecionar_medicoes, resumir_por_parametro, validar_resultado, carregar_resultado_json e comparar_experimentos.

Coloque classes e funções reutilizáveis em modelos.coral e importe os símbolos necessários em principal.coral. Configure o arquivo de entrada no coral.toml; esse caminho é independente do bloco opcional programa principal.

Resposta do capítulo 7

Altere a mensagem do primeiro programa e preveja a saída.

Troque apenas o texto entre aspas. O comando mostre imprime o novo texto; as aspas não aparecem na saída.

Resposta do capítulo 8

Diferencie parâmetro, argumento, padrão e retorno em uma ficha.

Parâmetro é o nome previsto pela função; argumento é o valor fornecido numa chamada; padrão é o valor usado quando um argumento opcional é omitido; retorno é o valor devolvido ao chamador.

Resposta do capítulo 9

Troque o valor inicial de 10 por 20 no exemplo de pontos. Antes de executar, preveja o resultado.

A saída será 23: o programa começa com vinte pontos, adiciona cinco e retira dois. A ordem das instruções continua sendo a mesma.

Resposta do capítulo 10

Diferencie uma lista que pode ser nula de uma lista cujos itens podem ser nulos.

lista de inteiro ou nulo permite nulo no valor externo; lista de (inteiro ou nulo) permite nulo dentro da lista. Essas anotações não convertem nem validam profundamente os valores em execução.

Resposta do capítulo 11

Calcule o dobro da soma de 3 e 4, preservando a ordem desejada.

Use (3 mais 4) vezes 2. O resultado é 14. Parênteses tornam a ordem explícita.

Resposta do capítulo 12

Altere a média do exemplo para 6 e para 4; acrescente rejeição de valor negativo.

Para 6, o ramo de recuperação é escolhido; para 4, o de reprovação. Antes da comparação de aprovação, teste se a média é menor que zero e informe valor inválido.

Resposta do capítulo 13

Mostre os inteiros de 0 até antes de 3 e explique a terminação.

Use para n de 0 até antes de 3 faça, mostre n e fim. A saída é 0, 1 e 2 em linhas separadas; o limite superior não é visitado.

Resposta do capítulo 14

Diferencie alterar uma lista e produzir outra lista.

Uma alteração muda o objeto compartilhado por referências. Uma operação que produz nova lista preserva a original; confira o campo Atenção da ficha antes de assumir qualquer uma das duas situações.

Resposta do capítulo 15

Crie uma função que receba um inteiro e devolva seu dobro.

Declare crie a função dobro com numero do tipo inteiro retornando inteiro, use retorne numero vezes 2 e feche com fim. Uma chamada com 21 devolve 42.

Resposta do capítulo 16

Explique a diferença entre instância, classe e atributo.

A classe descreve a estrutura e as operações; a instância é um objeto criado a partir dela; um atributo guarda parte do estado desse objeto. Duas instâncias podem manter estados diferentes.

Resposta do capítulo 17

Verifique se verdadeiro é do tipo inteiro.

O teste oficial e_tipo(verdadeiro, "inteiro") devolve falso. A superfície Coral não trata booleano como inteiro implícito.

Resposta do capítulo 18

Capture uma divisão por zero e imprima uma mensagem ao encerrar.

Use tente, a divisão, se der erro do tipo ZeroDivisionError com a mensagem, e finalmente para a mensagem final. O bloco final roda tanto no caso normal quanto na falha tratada.

Resposta do capítulo 19

Explique por que produzir números pode consumir menos memória que montar uma lista inteira.

Uma função geradora entrega um valor a cada solicitação e mantém apenas seu estado de execução. A economia existe quando o consumidor também processa os valores progressivamente.

Resposta do capítulo 20

Explique o papel de aguarde dentro de uma função assíncrona.

aguarde suspende a função até que a operação entregue um resultado, permitindo ao ciclo de eventos avançar outras tarefas. Não transforma um cálculo bloqueante em cálculo paralelo.

Resposta do capítulo 21

Coloque a função chamada abaixo do bloco programa principal. O que acontece ao importar o arquivo?

A execução direta inicializa o módulo inteiro e só depois inicia a entrada, portanto a função já está disponível. A importação disponibiliza os símbolos, mas não inicia o bloco principal.

Resposta do capítulo 22

Leia um nome e mostre uma saudação.

Leia uma linha com ler_linha("Nome: ") ou a forma natural equivalente. Guarde o texto e use mostre "Olá, " mais nome. A conversão é desnecessária para um nome.

Resposta do capítulo 23

Converta 12 e depois uma entrada inválida com padrão nulo.

inteiro("12") devolve 12. inteiro("inválido", nulo) devolve nulo. Sem o padrão, a entrada inválida produz ErroConversao.

Resposta do capítulo 24

Remova espaços externos de um texto e converta para maiúsculas.

aparar(" Coral ") devolve "Coral"; passar esse resultado para maiusculas devolve "CORAL". O texto original não é modificado.

Resposta do capítulo 25

Remova valores repetidos de [3, 1, 3, 2] e ordene o resultado.

unicos produz [3, 1, 2], conservando a primeira ocorrência. ordenar produz [1, 2, 3]. A lista original permanece igual.

Resposta do capítulo 26

Escreva Coral num arquivo e leia o conteúdo.

Use escrever_texto("dados.txt", "Coral") e ler_texto("dados.txt"). A escrita tem efeito no sistema de arquivos e a leitura devolve texto. Considere permissão, codificação e pasta de trabalho.

Resposta do capítulo 27

Converta um dicionário para JSON e reconstrua o valor.

Use para_json para obter texto JSON e de_json para recuperar o dicionário. A ida e volta preserva os valores compatíveis com JSON, não objetos arbitrários ou identidade de instância.

Resposta do capítulo 28

Calcule a média de 2, 4 e 6.

A soma é 12 e a quantidade é 3, portanto a média é 4. coral.matematica.media([2, 4, 6]) devolve 4.0. Não use uma coleção vazia.

Resposta do capítulo 29

Explique por que persistência não deve guardar callbacks e janelas ativas.

Esses objetos dependem de execução e recursos externos. O formato portátil guarda estado declarativo, com contrato e esquema, e reconstrói apenas os tipos que possuem adaptadores explícitos.

Resposta do capítulo 30

Diferencie arquivo de entrada, importação e bloco programa principal.

O projeto escolhe qual arquivo executar; a importação carrega um módulo; o bloco principal organiza a ação da execução direta. Bibliotecas reutilizáveis não devem iniciar a aplicação durante a importação.

Resposta do capítulo 31

Escreva uma verificação para uma função dobro e provoque uma falha intencional.

Use garanta que dobro(3) for igual a 6. Trocar 6 por 7 provoca a falha da verificação. Reponha o valor correto antes de considerar o teste aprovado.

Resposta do capítulo 32

Diferencie evento, regra e relógio de teste.

O evento registra um acontecimento; a regra escolhe como reagir; o relógio de teste permite controlar o tempo explicitamente. Uma passagem de tempo simulada não deve depender de espera real.

Resposta do capítulo 33

Modele dois objetos e uma relação fora do domínio de jogos.

Um laboratório pode modelar equipamentos e medições, com uma relação indicando o equipamento que gerou cada medição. Mundo oferece entidades e relações sem exigir janela ou combate.

Resposta do capítulo 34

Identifique os dados que devem ser reproduzíveis numa simulação de combate.

Estado inicial, participantes, regras, ordem de turno e semente ou resultados das jogadas precisam ser controlados. Uma vitória observada numa única execução não comprova equilíbrio.

Resposta do capítulo 35

Explique a vantagem de testar um jogo com BackendNulo.

O backend permite exercitar o estado e o fluxo sem janela nem renderização física. Ele não comprova desempenho gráfico ou funcionamento do dispositivo real.

Resposta do capítulo 36

Diferencie um vetor de posição e uma transformação em 3D.

O vetor representa coordenadas; a transformação especifica como alterar coordenadas. Em matrizes homogêneas, pontos e direções têm papéis diferentes e não devem ser confundidos.

Resposta do capítulo 37

Explique como semente e receita ajudam a reproduzir um campo procedural.

A semente controla o gerador e a receita registra algoritmo, versão e parâmetros. A reconstrução só é garantida para operações e versões suportadas; callbacks arbitrários não viram receita portátil.

Resposta do capítulo 38

Explique por que correlação com coluna constante é inválida.

O cálculo divide pela dispersão de cada variável. Se uma coluna não varia, essa dispersão é zero e a correlação não pode ser definida pelo contrato; a biblioteca produz diagnóstico.

Resposta do capítulo 39

Separe criar uma especificação de gráfico e salvar sua imagem.

Criar linha ou dispersao descreve os dados sem abrir janela. salvar escolhe o formato e renderiza. A disponibilidade do backend depende do formato solicitado.

Resposta do capítulo 40

Diferencie HTML local, cliente HTTP e servidor HTTP.

HTML local é conteúdo de apresentação; o cliente faz pedidos; o servidor responde a pedidos. Gerar HTML não abre conexão nem inicia um servidor.

Resposta do capítulo 41

Explique por que inventário simulado não comprova comunicação com uma placa física.

A simulação verifica o contrato do programa sem exercer cabo, porta, driver ou dispositivo. A comunicação física exige uma sessão de campo com aquele hardware.

Resposta do capítulo 42

Planeje um experimento com duas configurações e três repetições.

O plano contém seis execuções. Registre parâmetros, sementes, métricas e falhas; apresente diferenças como observações. Esse desenho não estabelece causalidade ou significância por si só.

APÊNDICE D: Migração desde a Coral 1.7.0

A 1.7.2 acrescenta expressões naturais para entrada, conversões, texto, coleções, JSON e consulta de tipos. As APIs explícitas permanecem válidas. A mudança é opcional e não exige reescrever programas existentes. Consulte os Caps. 17 e 22 a 27. Os diagnósticos de execução passam a manter uma classificação comum entre terminal e depurador; consulte o Cap. 18.

A 1.7.3 acrescenta coleções parametrizadas, tuplas estruturadas e nulidade opcional nas anotações, sem obrigar o uso de tipos. Atualize anotações onde elas tornarem a intenção mais clara e mantenha testes de dados recebidos. Consulte o Cap. 10.

Herança múltipla e chamadas cooperativas seguem MRO C3. Uma chamada ao pai continua a cadeia; ela não seleciona indiscriminadamente todas as bases. Construtores precisam cooperar explicitamente. Consulte o Cap. 16, seção Para ir além.

O bloco programa principal pode organizar a entrada de uma aplicação e permite declarar suas funções abaixo. Ele começa apenas na execução direta do módulo; scripts lineares continuam válidos. Consulte o Cap. 21.

A coleção deixa de ser um único volume. As referências internas passam a indicar capítulo e seção. Esta revisão preserva os livros anteriores e usa fontes compartilhadas para os dois volumes e a projeção local do site.

Migração para a Coral 1.7.4

Instale Coral Language 0.75.2 e confirme o runtime 1.7.4. As formas de escrever classes, imports e programa principal permanecem disponíveis. Revise novas advertências entre módulos usando as assinaturas reais. O realce semântico acompanha o tema e pode ser desativado. Ao reutilizar um projeto antigo, permita que o build regenere o cache de contratos.

Migração para a Coral 1.7.6

Instale Coral Language 0.77.0 e confirme o runtime 1.7.6. A forma objeto for do tipo Classe substitui a chamada comum e_tipo(objeto, Classe) quando isso melhorar a leitura; a API continua compatível. Consulte o Cap. 17, seção Consultar classes do programa.

Chamadas longas podem usar chame alvo com, argumentos indentados e fim; a forma compacta permanece válida. Consulte o Cap. 15, seção Chamadas explícitas em várias linhas. Essa mudança não exige migrar o código existente.

Os dois volumes são a edição oficial corrente. O livro único da 1.7.0 é histórico e permanece disponível para compatibilidade. Os relatórios da coleção registram a validação da edição e as lacunas normativas anteriores que ainda precisam de revisão.
